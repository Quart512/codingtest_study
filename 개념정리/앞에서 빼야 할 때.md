# 앞에서 빼야 할 때 무엇을 쓸까

> [!question] 언제 이 노트를 보나
> 리스트나 큐의 **맨 앞** 원소를 반복해서 꺼내야 하는 문제. 카드/줄서기/시뮬레이션/BFS 계열에서 계속 나온다.

## 결론 먼저

| 상황 | 선택 | 앞에서 빼기 비용 |
|---|---|---|
| 앞에서 **읽기만** 하면 됨 (꺼낸 걸 다시 안 씀) | **인덱스 포인터** | 없음 (안 뺌) |
| 실제로 꺼내야 하고, 양이 많음 | **`collections.deque`** | O(1) |
| 양이 적음 (수십 개 이하) | `list.pop(0)` 그대로 | O(n) — 하지만 티 안 남 |
| 중간에 자주 삽입/삭제 + 그 위치를 이미 알고 있음 | 연결 리스트 (파이썬에선 거의 안 씀) | O(1) |

관련 교과서: [[리스트]] · [[deque]] · [[연결 리스트]] · [[투 포인터]] · [[시간복잡도]]

## 왜 `list.pop(0)` 이 느린가

파이썬 리스트는 **한 줄로 붙어 있는 배열**이다. 맨 앞을 빼면 뒤에 있는 원소를 전부 한 칸씩 당겨야 한다.

```
[a][b][c][d][e]   <- pop(0)
   [b][c][d][e]   <- 이 4개를 전부 왼쪽으로 이동
[b][c][d][e]
```

원소가 n개면 한 번 뺄 때 최대 n번 이동 → **O(n)**.
이걸 n번 반복하면 **O(n²)**.

반대로 `pop()` (맨 뒤)는 당길 게 없어서 **O(1)** 이다. 그래서 스택은 리스트로 써도 전혀 문제없다.

## 그래서 deque 를 항상 써야 하나 — 아니다

`deque` 변환 자체가 O(n) 이고, 자료구조를 하나 더 들여오는 만큼 코드가 길어진다.
**n이 작으면 이득이 0이다.** 예: [[카드뭉치]] 는 카드가 최대 10장이라 `pop(0)` 100번 해도 순식간이다.

판단 기준:

- n ≤ 1,000 → 아무거나. 읽기 쉬운 걸로.
- n ≥ 100,000 이고 앞에서 빼야 함 → **deque 필수**. list 로 하면 시간 초과.
- 애초에 뺄 필요가 없음 → **포인터**. deque 보다도 낫다.

> [!tip] 코테에서 실제로 deque 를 쓰는 곳
> BFS 큐. 방문할 노드를 앞에서 꺼내고 뒤에 넣는 패턴이라 `popleft()` 가 정확히 맞는다.

## 연결 리스트는 언제 쓰나

"중간 삽입/삭제가 O(1)" 은 **삭제할 노드를 이미 손에 쥐고 있을 때**만 참이다.
찾아가는 데 O(n) 이 들면 결국 O(n) 이다. 그래서 실전에서 남는 용도는 좁다:

- LRU 캐시 (해시맵이 노드 주소를 들고 있어서 탐색 없이 바로 끊고 붙임)
- 요세푸스 문제류의 원형 연결 리스트
- 에디터의 undo/redo, 텍스트 버퍼

그리고 파이썬에서는 이런 경우조차 노드 클래스를 직접 만들기보다 `deque`(내부가 이중 연결 블록) 나 `OrderedDict` 를 쓴다. 직접 구현은 **자료구조 시험 대비용**이지 코테 풀이용이 아니다.

자세한 내용은 [[연결 리스트]] 로.
