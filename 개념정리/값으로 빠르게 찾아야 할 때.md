# 값으로 빠르게 찾아야 할 때

> [!question] 언제 이 노트를 보나
> 리스트에서 `.index()` 나 `in` 을 반복해서 쓰고 있는데, 입력이 커지면 느려지는 문제.

## 결론 먼저

| 상황 | 선택 |
|---|---|
| "이 값이 리스트 어디 있지?" 를 반복 조회 | list 대신 **dict** — 값 → 인덱스를 미리 저장 |
| "이 값을 본 적 있나?" 만 확인 | **set** |
| 값별로 개수·누적값을 세야 함 | **dict** (`collections.Counter` 도 가능) |

## 왜 list.index() 가 문제가 되나

`list.index(x)` 는 앞에서부터 하나씩 비교한다. 리스트 길이가 n이면 최악의 경우 n번 비교 → O(n).
이 조회를 반복문 안에서 m번 하면 전체는 O(n × m). n과 m이 둘 다 커지면 급격히 느려진다.

> [!tip] 알아채는 신호
> 채점 결과에서 작은 입력은 빠른데 큰 입력에서만 시간 초과가 나고, **입력이 커지는 폭보다 실행 시간이 훨씬 가파르게 늘어난다면** → 반복문 안의 `.index()` 나 `in list` 를 의심한다.

## 언제 쓰지 말아야 하나

- 값을 딱 한 번만 찾으면 된다. dict를 만드는 비용(O(n)) 자체가 낭비 — 그냥 한 번 순회
- 리스트가 원래 작다(수십 개 이하). O(n)이든 O(1)이든 체감 차이가 없다
- **순서·위치 자체가 중요한 조회.** dict는 키로 즉시 접근은 빠르지만 "몇 번째인지"는 따로 관리해야 한다

## 구현 골격

```python
index_of = {value: i for i, value in enumerate(lst)}
pos = index_of[target]        # O(1)
```

```python
seen = set(lst)
if target in seen:            # O(1)
    ...
```
