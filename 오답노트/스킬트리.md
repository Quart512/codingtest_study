## 풀이의 핵심

**순서에 없는 스킬을 지우고 나면, 남은 글자는 `skill` 의 앞부분이어야 한다.**

| 스킬트리 | 지운 뒤 | `skill` (`"CBD"`) 의 앞부분인가 |
|---|---|---|
| `"BACDE"` | `"BCD"` | 아니다 (B 가 C 보다 먼저) |
| `"CBADF"` | `"CBD"` | 맞다 |
| `"AECB"` | `"CB"` | 맞다 (D 를 아직 안 배운 것은 괜찮다) |
| `"BDA"` | `"BD"` | 아니다 (C 를 건너뜀) |

"앞부분" 이라서 두 가지가 한 번에 걸러진다. **순서가 바뀐 것**과 **중간을 건너뛴 것**.
끝까지 다 배울 필요는 없으니 `skill` 전체와 같을 필요는 없다.

선행 스킬을 하나도 안 배운 스킬트리(`"AEF"`)는 지우면 빈 문자열이 되고, `skill[:0]` 도 빈 문자열이라 **가능**으로 맞게 센다.

## 이렇게 했으면 어땠을까

### 1. 만약 거르기와 비교를 한 줄씩으로 쓴다면

```python
def solution(skill, skill_trees):
    answer = 0
    for tree in skill_trees:
        valid = "".join(s for s in tree if s in skill)
        if skill.startswith(valid):
            answer += 1
    return answer
```

- `"".join(...)` 은 조건에 맞는 글자만 이어 붙인다. `valid_skill += s` 를 반복하는 것과 같다
- `skill.startswith(valid)` 는 `skill[:len(valid)] == valid` 와 같다. 길이를 따로 구할 필요가 없다
- 빈 문자열은 모든 문자열의 앞부분이다. `"CBD".startswith("")` 는 `True`

무작위 20,000건에서 통과한 코드와 결과가 같았다. 입력이 작아서(스킬트리 20개, 각 26자 이하) 속도 차이는 없다.

## 배운 것

1. "상관없는 것은 아무 때나 와도 된다" 는 조건은 **상관없는 것을 지워 놓고** 보면 단순해진다
2. "순서대로, 건너뛰지 않고" 는 **앞부분이 같은가**(`startswith`) 하나로 검사할 수 있다
3. 문자열도 `in` 과 `for` 가 리스트처럼 된다
