## 이렇게 했으면 어땠을까

### 1. 만약 맨 위 4개를 슬라이스로 한 번에 비교한다면

```python
def solution(ingredient):
    answer = 0
    stack = []
    for i in ingredient:
        stack.append(i)
        if stack[-4:] == [1, 2, 3, 1]:
            del stack[-4:]
            answer += 1
    return answer
```

통과한 코드의 `len(stack) >= 4` 와 `if` 네 겹, `pop()` 네 번이 두 줄로 줄어든다.

- `stack[-4:]` 는 원소가 4개보다 적으면 **있는 만큼만** 돌려준다. 길이가 다른 리스트는 `==` 에서 거짓이라 **길이 검사를 따로 할 필요가 없다.**
  [[명예의전당1]] 에서는 "있는 만큼만 준다" 가 `IndexError` 의 원인이었는데, 여기서는 같은 성질이 경계 처리를 없애 준다. 차이는 그 뒤에 **인덱스로 집느냐, 통째로 비교하느냐**다
- `del stack[-4:]` 는 맨 뒤를 자르는 것이라 당겨 올 원소가 없다

속도는 같다. 길이 100만 입력에서 둘 다 0.1초 안팎 (로컬 측정).

### 2. 만약 스택 없이 "앞에서부터 찾아서 지우기" 를 반복한다면

```python
while True:
    for i in range(len(lst) - 3):
        if lst[i:i+4] == [1, 2, 3, 1]:
            del lst[i:i+4]      # 지우고 처음부터 다시 찾는다
            cnt += 1
            break
    else:
        break
```

답은 맞다. 하지만 하나 지울 때마다 **처음부터 다시 훑는다.**
햄버거가 겹겹이 들어 있는 입력 `[1,2]*k + [1,2,3,1] + [3,1]*k` 로 재 보면:

| 길이 | 찾아서 지우기 | 스택 |
|---|---|---|
| 4,004 | 0.07s | 0.0004s |
| 8,004 | 0.26s | 0.0008s |
| 16,004 | 1.12s | 0.0015s |
| 32,004 | 4.46s | 0.0030s |

길이가 2배가 될 때마다 시간이 4배 → **O(n²).** 재료는 최대 100만 개라 이 방식은 통과할 수 없다. 스택은 재료마다 맨 위 4개만 보므로 O(n) 이다.

**다시 훑을 필요가 없는 이유**: 새 재료를 하나 올렸을 때 햄버거가 완성될 수 있는 자리는 **맨 위 4개뿐**이다. 그 아래는 이미 올릴 때마다 검사를 마쳤다.
포장해서 4개를 빼면 그 아래 재료가 다시 맨 위가 되고, 다음 재료가 올라올 때 자연스럽게 다시 검사된다.

| 방식 | 시간복잡도 | 지운 뒤 | 언제 |
|---|---|---|---|
| 스택 (통과한 코드) | O(n) | 이어서 진행 | 방금 넣은 것 때문에 생기는 변화만 보면 될 때 |
| 앞에서부터 찾아 지우기 | O(n²) | 처음부터 다시 | 입력이 작을 때만 |

## 배운 것

1. **새로 들어온 것 때문에 달라질 수 있는 곳이 맨 끝뿐이면 스택이다.** 지우고 나서 처음부터 다시 볼 필요가 없다
2. 슬라이스는 범위를 벗어나도 에러가 아니라 **있는 만큼만** 준다. 통째로 비교하면 길이 검사가 필요 없고, 인덱스로 집으면 `IndexError` 가 난다
3. `append` / `pop()` / `del lst[-k:]` 처럼 **맨 뒤만** 건드리면 원소를 당기지 않는다 → [[앞에서 빼야 할 때]]
