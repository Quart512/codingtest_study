## 무엇을 틀렸나

### 1. `pass` 는 "취소" 가 아니라 "아무것도 안 함"

```python
for i in range(n):
    target[1]+=1
    if park_matrix[target[1]][target[0]] == 'X':
        pass            # 장애물을 찾았는데 아무 일도 안 일어난다
if target[1]<0 or target[1]>W:
    pass                # 범위를 벗어났는데 아무 일도 안 일어난다
```

장애물·범위 위반을 감지하는 `if` 는 맞게 썼는데, 안에 `pass` 를 넣었다.
`pass` 는 **"여기에 문장이 없다"** 는 뜻일 뿐이다. 자리를 비워 둘 때 문법 오류를 막는 용도지, 실행을 되돌리거나 건너뛰지 않는다.

게다가 이미 `target[1]+=1` 로 **이동을 저질러 놓은 뒤**라, 감지해 봐야 위치는 이미 바뀌어 있다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

되돌리는 코드를 짜는 대신, **애초에 옮기지 않는다.** → 5번의 해결

### 2. 행과 열을 바꿔서 접근

```python
park_matrix[target[1]][target[0]]     # target = [y, x] 인데 [x][y] 로 접근
```

2차원 리스트는 **`[행][열]`**, 즉 `[y][x]` 순서다. `target` 은 `[y, x]` 로 담아 놓고 꺼낼 때 뒤집어 썼다.

에러가 안 나서 더 위험했다. 1차 시도를 3×3 공원에 돌리면:

```
1차 시도 -> [2, 2]      (정답은 [2, 1])
```

**정사각형 격자에서는 터지지 않고 조용히 틀린 답이 나온다.** 직사각형이었다면 `IndexError` 로 바로 드러났을 것이다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

`[y][x]` 로 통일. 변수 이름도 `target[0]`, `target[1]` 대신 `y`, `x` 로 바꿔서 헷갈릴 여지를 없앴다. → [[IndexError - list index out of range]]

### 3. 시작점 'S' 를 찾지 않음 / 리스트 전체와 문자를 비교

1차 시도는 시작 위치를 `[0, 0]` 으로 고정했다. 공원에서 `S` 를 찾는 과정 자체가 없었다.

2차 시도에서 찾으려 했지만:

```python
for y in park_matrix:
    for x in y:
        if park_matrix=='S':        # 2차원 리스트 전체 == 문자 하나
            answer = [x, y]
```

- `if park_matrix=='S'` 는 **리스트 전체**를 문자열 `'S'` 와 비교한다. 언제나 거짓이라 `answer` 는 한 번도 만들어지지 않는다
- `for y in park_matrix` 의 `y` 는 **행 번호가 아니라 행 리스트**, `for x in y` 의 `x` 는 **열 번호가 아니라 글자**다. 그래서 `[x, y]` 는 좌표가 아니라 `['O', ['O','S','O']]` 같은 값이 된다

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

값이 아니라 **번호**로 돌면서, 그 번호로 원소를 꺼내 비교한다.

```python
for y in range(H):
    for x in range(W):
        if park_matrix[y][x] == 'S':
            answer = [y, x]
```

→ 위치가 필요하면 `for x in lst` 가 아니라 `for i in range(len(lst))` 또는 `enumerate`.

### 4. `target = answer` 는 복사가 아니다

```python
def check(direction, n):
    target=answer          # 같은 리스트를 가리킬 뿐
    ...
    target[1]+=1           # answer 도 같이 바뀐다
```

파이썬에서 `a = b` 는 **값을 복사하지 않는다.** 이름표를 하나 더 붙일 뿐이라 둘은 같은 리스트다.
그래서 "일단 `target` 으로 옮겨 보고, 문제가 있으면 `answer` 는 그대로 두자" 는 계획이 성립하지 않는다. 옮기는 순간 원본이 이미 오염된다.

복사가 필요하면 `target = answer[:]` 또는 `list(answer)`.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

복사본을 만들지 않았다. **원본을 건드리지 않고 `y`, `x` 라는 숫자 두 개만 꺼내서** 계산한다.

```python
y, x = answer[0], answer[1]      # 숫자는 복사된다. 리스트와 다르다
```

### 5. 검사를 이동한 뒤에 함 — 게다가 음수는 터지지도 않는다

```python
for i in range(n):
    target[1]-=1                               # 먼저 옮기고
    if park_matrix[target[0]][target[1]] == 'X':   # 그다음에 확인
```

- 오른쪽·아래로 넘어가면 `IndexError` 가 난다. 범위를 확인하는 `if` 에 **도달하기 전에** 터진다
- 왼쪽·위로 넘어가면 인덱스가 음수가 되는데, 파이썬은 이걸 **반대쪽 끝**으로 읽는다. `lst[-1]` 은 에러가 아니라 맨 뒤 원소다. 공원 왼쪽으로 나갔는데 오른쪽 끝 칸을 검사하게 되고, 에러 없이 틀린 답이 나온다

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

**순서를 뒤집는다. 옮기기 전에 다 확인하고, 통과하면 그때 한 번에 옮긴다.**

```python
if x + n >= W:                    # 1) 목적지가 공원 안인가
    return
for i in range(1, n + 1):         # 2) 가는 길에 장애물이 있는가
    if park_matrix[y][x + i] == 'X':
        return
answer = [y, x + n]               # 3) 둘 다 통과했을 때만 이동
```

이러면 `answer` 는 **유효한 위치에서만 바뀐다.** 되돌릴 일이 없으니 롤백 코드도, `obsticle` 같은 깃발 변수도 필요 없다.

### 6. 함수 안에서 바깥 변수에 대입하면 지역 변수가 된다

```python
def check(direction, n):
    target=answer
    ...
    if obsticle== False:
        answer = target      # 이 대입 때문에 answer 가 이 함수의 지역 변수로 취급된다
```

```
UnboundLocalError: local variable 'answer' referenced before assignment
```

함수 안에서 **어딘가 한 번이라도 대입**하면, 파이썬은 그 이름을 함수 전체에서 지역 변수로 본다.
그래서 맨 윗줄 `target=answer` 가 아직 만들어지지도 않은 지역 `answer` 를 읽으려다 터진다. 대입이 아래에 있어도 마찬가지다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

바깥 변수를 바꾸겠다고 선언한다.

```python
def check(direction, n):
    nonlocal answer
```

읽기만 할 때는 필요 없고, **대입할 때만** 필요하다.

## 이렇게 했으면 어땠을까

### 1. 만약 방향을 dict 으로 두었다면

지금 코드는 `E / W / N / S` 네 갈래가 거의 같은 내용을 반복한다. 한 군데를 고치면 나머지 세 곳도 같이 고쳐야 한다.

```python
D = {'N': (-1, 0), 'S': (1, 0), 'W': (0, -1), 'E': (0, 1)}

for move in routes:
    d, n = move.split()
    dy, dx = D[d]
    ny, nx = y + dy * int(n), x + dx * int(n)
    if not (0 <= ny < H and 0 <= nx < W):
        continue
    if any(park[y + dy*i][x + dx*i] == 'X' for i in range(1, int(n)+1)):
        continue
    y, x = ny, nx
```

**방향마다 다른 건 `(dy, dx)` 두 숫자뿐**이라는 걸 보면, 검사 로직은 한 벌만 있으면 된다.
2번(행/열 뒤바뀜)도 `[y][x]` 한 곳만 맞추면 되니 실수할 자리가 1/4로 줄어든다.

### 2. 시작점 찾기의 `break` 는 안쪽 반복만 멈춘다

```python
for y in range(H):
    for x in range(W):
        if park_matrix[y][x] == 'S':
            answer = [y, x]
            break          # 안쪽 for 만 끝난다. 바깥 for 는 끝까지 돈다
```

`S` 가 하나뿐이라 답은 맞지만, 의도는 "찾으면 그만두기" 였을 것이다.
두 겹을 한 번에 빠져나오려면 **함수로 빼서 `return`** 하는 게 가장 깔끔하다.

| 방식 | 두 겹 탈출 | 비고 |
|---|---|---|
| 안쪽 `break` | 안 됨 | 바깥은 계속 돈다 |
| 함수로 빼고 `return` | 됨 | 가장 읽기 쉽다 |
| 깃발 변수 | 됨 | 변수가 늘어난다 |

## 배운 것

1. `pass` 는 "건너뛰기" 나 "취소" 가 아니라 **"여기에 문장이 없다"** 는 뜻이다. 되돌리고 싶으면 애초에 바꾸지 않는다
2. **검사는 바꾸기 전에.** 먼저 확인하고 통과하면 한 번에 반영하면, 롤백 코드 자체가 없어진다
3. `a = b` 는 리스트를 복사하지 않는다. 복사는 `b[:]` 또는 `list(b)`
4. 파이썬에서 **음수 인덱스는 에러가 아니다.** 격자 왼쪽·위로 나가는 건 스스로 검사해야 한다
5. 값이 아니라 위치가 필요하면 `for x in lst` 가 아니라 `range(len(lst))` 또는 `enumerate`
6. 함수 안에서 바깥 변수에 **대입**하려면 `nonlocal`. 읽기만 할 땐 필요 없다
