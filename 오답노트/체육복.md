## 무엇을 틀렸나

### 1. 돌고 있는 리스트에서 `remove` — 다음 학생을 건너뛴다

```python
for l in lost:
    if l-1 in reserve:
        reserve.remove(l-1)
        lost.remove(l)        # 지금 for 가 돌고 있는 바로 그 리스트를 줄인다
```

에러는 나지 않는다. 공식 예제 1번에서 **조용히 틀린 답**이 나온다.

```
solution(5, [2, 4], [1, 3, 5])  ->  4      (정답은 5)
```

`print(l)` 을 찍어 보면 **2 한 번만** 찍히고 끝난다. 4번 학생은 검사조차 받지 않았다.

| for 가 볼 칸 | 그 순간의 `lost` | 꺼낸 값 | 한 일 |
|---|---|---|---|
| 0번 | `[2, 4]` | 2 | 1번에게 빌림 → `lost.remove(2)` |
| 1번 | `[4]` | 없음 | 1번 칸이 없다 → 반복 끝 |

`for l in lost` 는 원소를 기억하는 게 아니라 **"다음은 몇 번 칸"** 이라는 번호만 기억한다.
`remove` 로 앞이 빠지면 뒤 원소들이 한 칸씩 당겨지는데, 번호는 그대로 1 늘어난다.
그래서 **지운 원소 바로 뒤에 있던 원소**가 방금 본 자리로 들어오고, for 는 그 자리를 이미 본 것으로 치고 지나간다.

`reserve.remove(...)` 는 괜찮다. `reserve` 는 돌고 있는 리스트가 아니다.
문제는 **도는 리스트와 지우는 리스트가 같다**는 것 하나다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

`lost` 는 읽기만 하고, 빌린 학생은 **다른 리스트에 따로 모은다.**

```python
solved=[]
for l in lost:
    if l-1 in reserve:
        reserve.remove(l-1)
        solved.append(l)      # lost 는 그대로 둔다
...
answer=n-len(lost)+len(solved)
```

→ 순회하는 리스트는 건드리지 않는다. 뺄 것은 다른 곳에 적어 두고 반복이 끝난 뒤에 계산한다.

### 2. 1번을 고쳐도 테스트 5개 실패 (83%)

```python
def solution(n, lost, reserve):
    answer = 0
    solved=[]
    for l in lost:
        if l-1 in reserve:
            reserve.remove(l-1)
            solved.append(l)
        elif l in reserve:
            reserve.remove(l)
            solved.append(l)
        elif l+1 in reserve:
            reserve.remove(l+1)
            solved.append(l)
    answer=n-len(lost)+len(solved)
    return answer
```

공식 예제 3개는 전부 통과한다. 제출하면 5개가 실패한다.

**관찰**

모든 빌려주기 경우를 다 해 보는 풀이를 따로 짜서, 무작위 입력 20,000건으로 답을 비교했다.

| 입력 | 답이 다른 건수 |
|---|---|
| 전체 | 1,888 / 20,000 |
| 도난·여벌에 **겹치는 학생이 없는** 입력만 | 11 / 2,826 |
| 겹치는 학생이 없고 **정렬된** 입력만 | 0 / 2,826 |

- 틀리는 입력은 두 종류뿐이다. **(가) 도난당했는데 여벌도 있는 학생이 있을 때**, **(나) `lost` 가 정렬되어 있지 않을 때**
- 정답보다 크게도(652건), 작게도(1,236건) 나온다. 원인이 하나가 아니라는 뜻이다
- 프로그래머스에서 실패한 5개가 각각 어느 쪽인지는 확인하지 못했다 (채점 입력은 보이지 않는다)

**(가) 도난당했는데 여벌도 있는 학생**

```
solution(3, [1, 2], [2, 3])  ->  3      (정답은 2)
```

2번은 여벌이 있었지만 한 벌을 도난당했다. 남은 한 벌은 자기가 입어야 하므로 **빌려줄 수 없다** (제한사항 마지막 줄).
1번은 빌릴 사람이 없어서 수업을 못 듣는 게 맞다.

| 차례 | 한 일 | `reserve` |
|---|---|---|
| 1번 | 2번의 여벌을 가져감 | `[3]` |
| 2번 | 자기 것이 없어져서 3번에게 빌림 | `[]` |

2번이 입어야 할 한 벌이 1번에게 넘어갔다. 결과적으로 **3번의 여벌이 두 칸 떨어진 1번까지 간 셈**이다.

`elif` 순서를 바꿔 `l in reserve` 를 맨 위로 올려도 이 입력은 그대로 3이 나온다. 1번 차례에 2번의 여벌이 이미 나가기 때문이다.
지금 순서(`l-1` 이 먼저)에서는 반대 방향으로도 같은 일이 생긴다.

```
solution(3, [2, 3], [1, 2])  ->  3      (정답은 2)
```

**(나) 정렬되지 않은 입력**

```
solution(5, [3, 1], [4, 2])  ->  4      (정답은 5)
```

3번이 먼저 2번의 여벌을 가져가면, 1번은 빌릴 곳이 없어진다. 1번 ← 2번, 3번 ← 4번 으로 나누면 전원이 듣는다.
같은 학생들을 `[1, 3]` 순서로 주면 5가 나온다. **제한사항에 번호가 정렬되어 있다는 말은 없다.**

**왜 그렇게 생각했나**

"`elif l in reserve` 가 있으니 여벌이 있는 학생은 자기 것을 자기가 챙긴다."
"옆 학생이 먼저 가져가더라도 **어차피 수만 세면 되니까** 누가 입든 상관없다."

→ 둘 다 틀렸다.

- `elif l in reserve` 는 **자기 차례가 왔을 때만** 실행된다. 앞 학생이 `l+1` 로 이미 가져갔으면 그 줄은 거짓이다
- 사람만 바뀌고 수가 같은 건 **뺏긴 학생이 다시 빌릴 곳이 없을 때뿐**이다. `(3, [1, 2], [2])` 는 2번 대신 1번이 입을 뿐이라 답이 2로 같다.
  다시 빌릴 곳이 있으면 여벌이 **두 칸**을 건너간다. 앞뒤 번호에게만 빌려줄 수 있는 문제라서, 몇 벌인지뿐 아니라 **누구 손에 있는지**가 답을 바꾼다

**해결**

두 가지를 반복문 **앞에** 둔다.

- (가) 누구도 빌리기 전에, 양쪽에 다 있는 학생을 먼저 뺀다. 반복문 안의 한 갈래로는 순서를 보장할 수 없다
- (나) `lost.sort()`

정렬이 필요한 이유: 번호순으로 보면, 왼쪽 학생(`l-1`)의 여벌은 **지금 안 쓰면 뒤의 누구도 못 쓴다.** 오른쪽 학생(`l+1`)의 여벌은 `l+2` 가 쓸 수도 있다.
그래서 왼쪽 것부터 쓰는 게 손해가 없다. 이 논리가 **앞 번호부터 차례로 본다**는 전제 위에 서 있다.
오른쪽을 먼저 보면 정렬해도 틀린다: `(4, [2, 4], [1, 3])` → 3 (정답 4).

다만 (가)를 처음엔 반만 했다 → 3번. 최종 코드는 **3번의 해결**.

### 3. 겹치는 학생을 `lost` 에서만 뺐다 — `reserve` 에 남아 계속 빌려준다

```python
solved=[]
for r in reserve:
    if r in lost:
        solved.append(r)
for s in solved:
    lost.remove(s)          # reserve 에는 그대로 남는다
```

```
solution(2, [1, 2], [2])  ->  2      (정답은 1)
```

| 단계 | `lost` | `reserve` |
|---|---|---|
| 겹치는 학생(2번)을 `lost` 에서 뺌 | `[1]` | `[2]` |
| 1번: `l+1 in reserve` 참 → 2번 것을 가져감 | `[1]` | `[]` |

"잃어버린 학생" 명단에서는 지웠지만 "빌려줄 수 있는 학생" 명단에는 남아 있다. 2번이 입어야 할 한 벌이 또 1번에게 갔다.

정답 풀이와 비교한 무작위 20,000건 중 7,161건이 달랐고, **전부 정답보다 크게** 나왔다. 못 빌려줄 학생이 빌려준 경우뿐이라는 뜻이다.

1번 실수는 여기서 다시 하지 않았다. `solved` 에 모아 두고 **다른 반복문에서** `lost.remove(s)` 를 하므로, 도는 리스트(`solved`)와 지우는 리스트(`lost`)가 다르다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

```python
for s in solved:
    lost.remove(s)
    reserve.remove(s)
```

→ 두 명단에 걸쳐 있는 것을 뺄 때는 **양쪽에서 다** 뺀다. 한쪽에만 남으면 그쪽 역할은 계속한다.

## 이렇게 했으면 어땠을까

### 1. 만약 처음부터 set 의 차집합으로 나눈다면

```python
def solution(n, lost, reserve):
    lost_only = sorted(set(lost) - set(reserve))
    spare = set(reserve) - set(lost)
    for l in lost_only:
        if l - 1 in spare:
            spare.remove(l - 1)
        elif l + 1 in spare:
            spare.remove(l + 1)
        else:
            n -= 1
    return n
```

세 실수가 **생길 자리가 없어진다.**

| 내가 틀린 것 | 이 풀이에서는 |
|---|---|
| 1번 돌면서 `remove` | 차집합은 **새 집합을 만든다.** 원본을 돌면서 지울 일이 없다 |
| 2번 겹치는 학생이 빌려줌 | 반복문에 들어가기 전에 이미 양쪽에서 빠져 있다 |
| 2번 정렬 안 함 | 차집합 결과는 set 이라 순서를 믿을 수 없다. 리스트로 되돌리는 자리에 `sorted()` 가 자연스럽게 들어간다 |
| 3번 한쪽에서만 뺌 | `A - B` 와 `B - A` 를 **짝으로** 쓴다. 한쪽만 빼는 모양이 나오지 않는다 |

`spare.remove(...)` 는 반복 중에 지우지만 괜찮다. 도는 건 `lost_only` 고 지우는 건 `spare` 다.

### 2. 통과한 코드에서 `elif l in reserve` 는 이제 실행되지 않는다

겹치는 학생을 양쪽에서 뺀 뒤에는 `lost` 의 어떤 학생도 `reserve` 에 없다. 그 갈래는 **언제나 거짓**이다.
지워도 결과가 같다 (무작위 20,000건에서 확인). 틀린 건 아니고, 2번을 고치기 전 흔적이 남은 것이다.

같은 이유로 `solved` 리스트도 길이만 쓰니 숫자 하나(`count += 1`)면 된다.

### 3. 고려했지만 과했던 방법: 겹치는 학생을 정렬로 앞에 보내기

```python
lost.sort(key=lambda l: (l not in reserve, l))     # 겹치는 학생 먼저, 그 안에서 번호순
```

겹치는 학생이 전부 앞에 오면, 다른 학생이 빌리기 전에 각자 자기 여벌을 챙긴다. 따로 빼지 않아도 된다.

단, **`l in reserve` 를 `elif` 맨 위로 올려야만** 성립한다. 지금 순서(`l-1` 먼저)에서는 앞에 와도 자기 것 대신 옆 사람 것을 가져간다.

```
solution(3, [3, 1], [3, 2])  ->  2      (정답은 3)
```

| 방식 | 맞물려야 하는 조건 | 한쪽만 바꾸면 |
|---|---|---|
| 겹치는 학생을 먼저 뺌 (통과한 코드) | 없음 | 해당 없음 |
| 정렬 기준으로 앞에 보냄 | 정렬 기준 + `elif` 순서 | 에러 없이 틀린 답 |

떨어진 두 줄이 서로에게 기대는 구조는, 한 줄만 고쳤을 때 조용히 깨진다.

## 배운 것

1. **돌고 있는 리스트에서는 지우지 않는다.** 에러 없이 다음 원소를 건너뛴다. 지울 것은 따로 모았다가 다른 반복문에서 지우거나, 새 리스트·집합을 만든다
2. 공식 예제를 통과해도 끝이 아니다. **제한사항의 "~할 수 있습니다" 한 줄**이 숨은 테스트다
3. 수만 세는 문제여도 **거리 제한**이 있으면 누가 들고 있는지가 답을 바꾼다
4. 두 명단에 걸친 것을 뺄 때는 **양쪽에서 다** 뺀다
5. 정렬되어 있다는 말이 없으면 정렬되어 있지 않다. "앞에서부터 차례로" 고르는 풀이는 정렬을 전제로 한다
