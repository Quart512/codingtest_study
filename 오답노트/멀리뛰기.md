## 무엇을 틀렸나

### 1. 공식으로 더하려다 — n 이 6 이상이면 반복문이 끝나지 않는다

```python
def solution(n):
    answer = 1 + n-1
    left=(2,n-1)

    #1 + n-1 + (n-1)(n-3)/2 + (n-1)(n-3)(n-5)/3*2 +
    while left[1]*(left[1]-2)/left[0]>0 and left[1]-2>0:
        left=(left[0]+1, left[1]*(left[1]-2)/left[0])
        answer+=left[1]
    return answer%1234567
```

2칸 점프를 몇 번 쓰는지로 나눠서 경우의 수를 더하려 했다. 채점 결과는 시간 초과.

반복 횟수에 제한을 걸고 돌려 보면:

| n | 이 코드 | 정답 |
|---|---|---|
| 1, 2, 3 | 1, 2, 3 | 1, 2, 3 |
| 4 | 5.5 | 5 |
| 5 | 12.11 | 8 |
| 6 이상 | 200번 돌아도 끝나지 않음 | 13, 21, … |

- **느린 게 아니라 무한 반복이다.** `left[1]` 이 매번 거의 제곱씩 커져서 금방 소수(float)의 한계를 넘어 `inf` 가 된다. `inf*(inf-2)/k > 0` 은 언제나 참이라 `while` 이 끝나지 않는다
- **항도 틀렸다.** 2칸을 k번 쓰면 점프는 모두 n−k번이고, 그중 어느 k번이 2칸인지 고르는 것이라 **C(n−k, k)** 다. n=4 의 셋째 항은 `(n-1)(n-3)/2 = 1.5` 가 아니라 C(2, 2) = 1
- `/` 는 결과가 언제나 소수다. 정수로 나누려면 `//`

### 2. 변수 이름을 바꾸고 `return` 만 옛 이름으로 남겼다 — 런타임 에러

```python
    one,two=1,2
    ...
    return a           # NameError: name 'a' is not defined
```

참고한 코드의 `a`, `b` 를 `one`, `two` 로 바꾸면서 마지막 줄을 놓쳤다. 프로그래머스에서는 `NameError` 가 **런타임 에러**로만 보인다.

**해결**

```python
    return one
```

→ 이름을 바꿀 때는 그 이름이 나오는 곳을 **전부** 찾는다. 에디터의 "모두 바꾸기"를 쓰면 빠뜨리지 않는다.

## 풀이 이해하기

포인트는 두 개다.

### 포인트 1. 마지막 점프로 나눈다

n칸에 도착하는 모든 방법은 **마지막 점프가 1칸이거나 2칸**이다. 둘이 겹치지도 않고, 빠지는 것도 없다.

- 마지막이 1칸 → 그 전에 **n−1칸**까지 간 방법 하나하나 뒤에 `1` 을 붙인 것
- 마지막이 2칸 → 그 전에 **n−2칸**까지 간 방법 하나하나 뒤에 `2` 를 붙인 것

그래서 **n칸 방법 수 = (n−1칸 방법 수) + (n−2칸 방법 수).**

n=4 로 직접 보면:

| 마지막 점프 | 그 전까지 간 방법 | 붙이면 |
|---|---|---|
| 1칸 | 3칸: `111`, `12`, `21` | `1111`, `121`, `211` |
| 2칸 | 2칸: `11`, `2` | `112`, `22` |

3 + 2 = 5. 이 식 하나로 작은 칸부터 차례로 채워 가는 방식을 **DP(동적 계획법)** 라고 부른다. 앞에서 구한 답을 다음 답을 만드는 데 다시 쓴다.

### 포인트 2. 앞 두 칸만 들고 한 칸씩 전진한다

다음 칸을 만드는 데는 **바로 앞 두 칸**만 필요하다. 그래서 변수 두 개만 들고 간다.

- `one` = 지금 칸의 방법 수, `two` = 그다음 칸의 방법 수
- 한 바퀴 돌 때마다 `one, two = two, one + two` → 둘 다 한 칸씩 앞으로

n=5 로 따라가면:

| 바퀴 | `one` (몇 칸) | `two` (몇 칸) |
|---|---|---|
| 시작 | 1 (1칸) | 2 (2칸) |
| 1 | 2 (2칸) | 3 (3칸) |
| 2 | 3 (3칸) | 5 (4칸) |
| 3 | 5 (4칸) | 8 (5칸) |
| 4 | 8 (5칸) | 13 (6칸) |

시작할 때 `one` 이 1칸이므로, n칸까지 가려면 **n−1바퀴**. 그래서 `range(n-1)` 이고 답은 `one` 이다.

`one, two = two, (one + two)` 는 **오른쪽을 먼저 다 계산한 뒤** 한꺼번에 넣는다. 그래서 `one + two` 에는 바뀌기 전 값이 들어간다. 두 줄로 나눠 쓰면 이게 깨진다.

### 덧붙여. 나머지는 마지막에 한 번

```python
        one,two=two,(one+two)
    return one % 1234567
```

처음 통과한 코드는 더할 때마다 `% 1234567` 을 했다. 읽기 어려워서 **마지막에 한 번**으로 바꿨다. n = 1 부터 2,000 까지 답이 같다 (로컬 확인).

이렇게 해도 되는 건 **파이썬 정수에 크기 제한이 없어서**다. 중간 값이 n=2,000 에서 418자리까지 커져도 넘치지 않는다.
다만 숫자가 커질수록 덧셈 한 번이 느려진다. 로컬에서 잰 시간:

| n | 더할 때마다 | 마지막에 한 번 |
|---|---|---|
| 2,000 | 0.0001s | 0.0001s |
| 100,000 | 0.0025s | 0.0833s |
| 300,000 | 0.0076s | 0.7429s |

이 문제는 n 이 2,000 이하라 차이가 없다. n 이 수십만이면 더할 때마다 하는 쪽이 낫고, **C++·Java 처럼 정수 크기가 정해진 언어에서는 넘쳐서 틀린 답이 나오므로** 반드시 더할 때마다 해야 한다.

더할 때마다 해도 되는 이유: 더한 뒤 나머지를 구하든, 나머지끼리 더한 뒤 나머지를 구하든 결과가 같다.

## 이렇게 했으면 어땠을까

### 1. 만약 표를 리스트로 다 적는다면

```python
def solution(n):
    dp = [0, 1, 2] + [0] * n             # dp[i] = i칸에 가는 방법 수
    for i in range(3, n + 1):
        dp[i] = (dp[i - 1] + dp[i - 2]) % 1234567
    return dp[n]
```

포인트 1 의 식을 그대로 옮긴 모양이라 읽기 쉽다. 통과한 코드는 이 리스트에서 **앞 두 칸만 남기고 버린 것**이다.

### 2. 처음 생각한 공식을 맞게 고친다면

```python
import math
def solution(n):
    return sum(math.comb(n - k, k) for k in range(n // 2 + 1)) % 1234567
```

방향은 맞았다. 2칸을 k번 쓰는 경우의 수 C(n−k, k) 를 k = 0 부터 n//2 까지 더하면 된다. `math.comb` 는 정수로 정확하게 계산한다.
다만 중간 합이 아주 큰 수(n=2,000 이면 418자리)가 되고, 이 문제가 보려는 풀이는 아니다.

세 방식 모두 n = 1 부터 2,000 까지 결과가 같았다.

## 배운 것

1. 경우의 수 문제는 **마지막 한 걸음**으로 나눠 본다. "n 을 만드는 방법 = 한 걸음 전 상태들의 방법 합"
2. 다음 값에 앞의 몇 개만 필요하면 그 **몇 개만 들고 전진**한다
3. `a, b = b, a + b` 는 오른쪽을 다 계산한 뒤 넣는다
4. 파이썬은 정수가 넘치지 않아서 나머지를 **마지막에 한 번**만 구해도 답은 같다. 숫자가 아주 커지는 입력이거나 다른 언어라면 **더할 때마다**
5. 소수 나누기 `/` 를 반복하면 `inf` 가 되어 조건이 영원히 참일 수 있다. 정수 계산은 `//`
6. 변수 이름을 바꾸면 나오는 곳을 전부 바꾼다
