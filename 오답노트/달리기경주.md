### 1. 시간 초과 (테스트 9~13)

```python
def solution(players, callings):
    answer = []
    for calling in callings:
        called = players.index(calling)
        players[called-1], players[called] = players[called], players[called-1]
    answer = players
    return answer
```

로직은 맞다. 테스트 16개 중 11개가 통과했고, 틀린 답을 낸 케이스는 하나도 없다.

### 2. KeyError: None — 스왑 방향이 반대

`index()` 가 느린 걸 해결하려고 딕셔너리로 갈아탔다.

```python
def solution(players, callings):
    answer = []

    players_dict = {player: i for i, player in enumerate(players)}
    for calling in callings:
        key = next((k for k, v in players_dict.items() if v == players_dict[calling]+1), None)
        players_dict[calling] = players_dict[calling]+1
        players_dict[key] = players_dict[key]-1

    answer = players_dict
    return answer
```

`KeyError: None` 이 떴다. 그런데 **이건 증상이지 원인이 아니다.**

**원인**

딕셔너리의 값은 **인덱스**다. 인덱스 0 = 1등.
그러니까 **추월 = 인덱스가 줄어드는 것**이다.

그런데 `players_dict[calling]+1` 을 찾고 있었다.
이건 뒤에 있는 선수를 찾아서 `calling` 을 한 칸 **뒤로** 보내는 코드다.
추월이 아니라 **추월당하는** 로직을 짠 것.

`print` 를 찍어서 한 스텝씩 따라가 보면 바로 보인다:

```
before: {'mumu':0, 'soe':1, 'poe':2, 'kai':3, 'mine':4}  calling: kai
  찾은 key: mine            → kai 를 4번(꼴찌)으로 보냄
before: {'mumu':0, 'soe':1, 'poe':2, 'kai':4, 'mine':3}  calling: kai
  찾은 key: None            → 인덱스 5인 사람은 없음
KeyError: None
```

`kai` 가 꼴찌까지 밀려난 뒤 또 불리니 `v == 5` 인 선수가 없고,
`next(..., None)` 이 기본값 `None` 을 돌려줘서 `players_dict[None]` 에서 터졌다.

**왜 그렇게 생각했나**

"추월했다 = 순위 숫자가 올라간다" 로 읽고 `+1` 을 썼다.
하지만 딕셔너리에 담은 건 **순위가 아니라 인덱스**였다.
1등이 1이 아니라 0인 자료구조에서, 앞으로 가는 건 `-1` 이다.
**내가 저장한 값이 무엇인지**를 확인하지 않고 의미를 짐작한 게 원인.

**해결**

방향만 뒤집으면 정확성은 통과한다.

```python
key = next((k for k, v in players_dict.items() if v == players_dict[calling]-1), None)
players_dict[calling] -= 1
players_dict[key] += 1
```

1등은 추월할 대상이 없어서 `callings` 에 등장하지 않는다.
그래서 `-1` 로 고치면 `None` 이 나올 상황 자체가 사라진다.

### 3. 고쳐도 여전히 시간 초과 — dict 을 반쪽만 썼다

2번을 `-1` 로 고쳐도 제출하면 또 시간 초과다.

```python
key = next((k for k, v in players_dict.items() if v == players_dict[calling]-1), None)
```

이 한 줄이 **매번 딕셔너리 전체를 훑는다.** O(n)이다.
`index()` 를 없애려고 딕셔너리를 썼는데, 그 자리에 똑같이 O(n)짜리 전체 탐색을 다시 넣은 셈.
선수 5만 명 × 부름 100만 번 = O(n×m). 1번과 복잡도가 같다.

**원인**

딕셔너리로 만든 건 `이름 → 인덱스` 방향 하나뿐이다.
그런데 이 문제는 **`인덱스 → 이름`** 도 필요하다. 앞 선수가 누구인지 알아야 하니까.
없는 방향을 전체 탐색으로 때우는 순간 해시를 쓴 의미가 사라진다.

**해결**

`인덱스 → 이름` 은 `players` 리스트가 이미 갖고 있다. 새로 만들 필요가 없다.
리스트와 딕셔너리를 **항상 짝으로 갱신**하면 된다.

```python
def solution(players, callings):
    rank = {p: i for i, p in enumerate(players)}   # 이름 -> 인덱스
    for c in callings:
        i = rank[c]
        front = players[i-1]                       # 앞 선수: O(1)
        players[i-1], players[i] = players[i], players[i-1]
        rank[c], rank[front] = i-1, i              # 딕셔너리도 같이 갱신
    return players
```

부름 한 번당 전부 O(1). 전체 O(n+m).

그리고 2번 코드는 `answer = players_dict` 로 **딕셔너리를 반환**하고 있었다.
정답은 이름 리스트여야 한다. 시간 초과에 가려서 이 오류는 드러나지도 않았다.
