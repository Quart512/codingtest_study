## 무엇을 틀렸나

### 1. 실행조차 안 된 세 줄 — 메서드 이름, 대입 방향, `insert` 의 인자

```python
numbers.revert()                 # AttributeError: 'list' object has no attribute 'revert'
numbers[:]=numberss              # NameError: name 'numberss' is not defined
answer.insert(numbers[0])        # TypeError: insert expected 2 arguments, got 1
```

- 뒤집기는 `reverse()` 다
- 대입은 **왼쪽이 받는 쪽**이다. `numbers[:] = numberss` 는 아직 없는 `numberss` 를 읽어서 `numbers` 의 내용을 덮어쓰려는 문장이다
- `insert` 는 **위치와 값** 두 개를 받는다. 뒤에 붙이는 건 `append`

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

```python
numbers.reverse()
numberss=numbers[:]
answer.append(numberss[-1])
```

### 2. 보는 쪽(`[0]`)과 빼는 쪽(`pop()`)이 달랐다

```python
if numberss[0]>numbers[0]:       # 맨 앞을 본다
    ...
else:
    numberss.pop()               # 맨 뒤를 뺀다
```

리스트를 뒤집어 놓고 `pop()` 으로 한 칸씩 넘어가는 설계였다. `pop()` 은 **맨 뒤**를 빼므로 지금 볼 숫자도 맨 뒤(`[-1]`)에 있다.
`[0]` 은 아무리 `pop()` 을 해도 바뀌지 않는다.

같이 고친 것: 큰 수를 찾았을 때 넣는 값. `numbers[-1]`(지금 숫자)이 아니라 `numberss[-1]`(찾은 큰 수)이다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

```python
if numberss[-1]>numbers[-1]:
    answer.append(numberss[-1])
```

→ `pop()` 으로 줄여 가는 리스트는 **`[-1]` 로 본다.** 보는 끝과 빼는 끝을 맞춘다.

### 3. `-1` 을 넣는 자리 — `while` 안에 두면 건너뛸 때마다 들어간다

```python
while numberss:
    if numberss[-1]>numbers[-1]:
        answer.append(numberss[-1])
        break
    else:
        numberss.pop()
    answer.append(-1)            # 숫자 하나를 건너뛸 때마다 실행된다
```

```
solution([2, 3, 3, 5])  ->  [-1, 3, -1, -1, 5, -1, 5, -1]      (정답은 [3, 5, 5, -1])
```

`-1` 은 "끝까지 봤는데 없었다" 일 때 **한 번만** 들어가야 한다. 그 전 시도에서는 반대로 반복문 전체가 끝난 뒤 맨 밖에 한 번만 두었다.

**왜 그렇게 생각했나**

`while` 에 `else` 를 붙일 수 있는지 몰랐다.

**해결**

```python
while numberss:
    if numberss[-1]>numbers[-1]:
        answer.append(numberss[-1])
        break
    else:
        numberss.pop()
else:                            # while 의 짝. break 없이 끝났을 때만
    answer.append(-1)
```

→ "끝까지 찾았는데 없었다" 는 반복문의 `else` 에 적는다. [[반복문의 else]]

### 4. 시간 초과

```python
def solution(numbers):
    answer = []
    numbers.reverse()
    while numbers:
        numberss=numbers[:]
        while numberss:
            if numberss[-1]>numbers[-1]:
                answer.append(numberss[-1])
                break
            else:
                numberss.pop()
        else:
            answer.append(-1)
        numbers.pop()

    return answer
```

1–3번을 고친 코드. 제출하면 시간 초과가 난다. 어느 테스트가 실패했는지는 기록하지 못했다.

**관찰**

- **답은 맞다.** 공식 예제 2개와, 이중 반복문으로 짠 풀이와 비교한 무작위 20,000건이 전부 일치한다
- 복사본에 지금 숫자 자신이 들어 있지만 문제없다. 조건이 `>` 라서 자기 자신은 큰 수가 될 수 없고, `pop()` 으로 빠진 뒤 다음으로 넘어간다
- 느린 건 입력 모양과 상관없다. 로컬에서 잰 시간:

| 길이 | 내림차순 (뒤에 큰 수가 없음) | 오름차순 (바로 뒤가 큰 수) |
|---|---|---|
| 5,000 | 0.39s | 0.010s |
| 10,000 | 1.54s | 0.042s |
| 20,000 | 6.32s | 0.175s |
| 40,000 | 25.97s | 0.728s |

- 두 경우 모두 길이가 2배가 될 때마다 시간이 약 4배 → **O(n²)**
- 오름차순은 첫 비교에서 바로 답을 찾는데도 4배씩 늘어난다. **찾기 전에 `numbers[:]` 로 뒤 전체를 복사하는 것만으로 이미 O(n)** 이기 때문이다. 숫자마다 한 번씩 복사하니 n × n
- 숫자는 최대 1,000,000개. 이 방식은 다듬어서 될 문제가 아니다

**왜 그렇게 생각했나**

시간 초과가 날 걸 알고 일부러 먼저 만들었다. 느린 버전을 끝까지 맞게 만들어 두고, 그다음 풀이에서 무엇이 바뀌는지 비교하려고.

**해결**

**뒤에서부터 돌고, 복사본 대신 스택 하나를 끝까지 들고 간다.** 안쪽 `while`-`else` 모양은 그대로 쓴다.

복사가 필요했던 건 **앞에서부터** 돌았기 때문이다. 이번 숫자에게 작아서 버린 수가 다음 숫자에게는 답일 수 있다.
뒤에서부터 돌면 달라진다. 지금 숫자 `x` 보다 작거나 같은 후보는 **다시는 누구의 답도 될 수 없다.**
그 왼쪽 숫자들에게는 `x` 가 더 가깝고 적어도 같은 크기라서, 그 후보보다 `x` 가 먼저 답이 된다. 그래서 한 번 버리면 끝이다.

`[9, 1, 5, 3, 6, 2]` 를 뒤에서부터:

| 지금 숫자 | 버린 후보 | 답 | 넣은 뒤 스택 |
|---|---|---|---|
| 2 | 없음 | -1 | `[2]` |
| 6 | 2 | -1 | `[6]` |
| 3 | 없음 | 6 | `[6, 3]` |
| 5 | 3 | 6 | `[6, 5]` |
| 1 | 없음 | 5 | `[6, 5, 1]` |
| 9 | 1, 5, 6 | -1 | `[9]` |

답이 뒤에서부터 쌓이므로 마지막에 뒤집는다.

다만 바로 되지는 않았다. 두 번 더 틀렸다 → 5번, 6번. 최종 코드는 **6번의 해결**.

### 5. 방향만 바꾸고 복사는 남겼다 — 전부 0

```python
while numbers:
    stack=numbers[:]             # 여전히 숫자마다 복사
    while stack:
        if stack[0]>numbers[0]:  # 복사본이라 stack[0] 과 numbers[0] 은 같은 숫자
            ...
    else:
        answer.append(0)         # -1 이어야 한다
    numbers.pop()
answer.reverse                   # 괄호가 없다
```

```
solution([2, 3, 3, 5])  ->  [0, 0, 0, 0]      (정답은 [3, 5, 5, -1])
```

- `stack` 은 `numbers` 의 복사본이라 `stack[0] > numbers[0]` 은 **언제나 거짓**이다. 빌 때까지 `pop()` 만 하고 `else` 로 간다
- 4번의 해결에서 바꿔야 했던 핵심(복사하지 않기)이 그대로 남아 있었다
- `answer.reverse` 는 괄호가 없어서 **실행되지 않는다.** 메서드를 가리키기만 하고 에러도 나지 않는다

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

반복문 안의 복사를 지우고, 맨 위의 `stack = []` 하나를 끝까지 쓴다. 비교는 맨 뒤끼리(`stack[-1]`, `numbers[-1]`), 없으면 `-1`, `answer.reverse()`.

### 6. 스택에 넣는 줄이 빠졌다 — 전부 -1

```python
    else:
        answer.append(-1)
    numbers.pop()                # 빼기만 하고 stack 에 넣지 않는다
```

```
solution([2, 3, 3, 5])  ->  [-1, -1, -1, -1]      (정답은 [3, 5, 5, -1])
```

스택이 처음부터 끝까지 비어 있다. 지금 숫자는 **왼쪽 숫자들의 후보**가 되어야 하는데 아무도 넣지 않았다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

```python
    stack.append(numbers.pop())  # 꺼낸 값을 바로 스택에
```

`pop()` 은 꺼낸 값을 돌려주므로 빼기와 넣기가 한 줄이다. 넣는 시점은 답을 정한 **뒤**. 앞에서 넣으면 자기 자신이 스택 맨 위에 있게 된다.

4번의 느린 버전과 비교 (로컬 측정):

| 길이 | 입력 | 4번 (숫자마다 복사) | 6번 (스택) |
|---|---|---|---|
| 40,000 | 내림차순 | 25.97s | 0.006s |
| 40,000 | 오름차순 | 0.728s | 0.004s |
| 1,000,000 | 내림차순 | 재지 않음 | 0.157s |
| 1,000,000 | 무작위 | 재지 않음 | 0.126s |

안쪽에 `while` 이 있는데도 O(n) 이다. **어떤 숫자든 스택에 한 번 들어가고 많아야 한 번 빠진다.** 숫자 하나에서 여러 개를 버릴 수는 있지만, 전부 합쳐서 버리는 횟수는 숫자 개수를 넘지 못한다.

## 이렇게 했으면 어땠을까

### 1. 만약 앞에서부터 돌면서 "답을 못 찾은 위치" 를 쌓는다면

```python
def solution(numbers):
    answer = [-1] * len(numbers)
    stack = []                                # 아직 답을 못 찾은 위치
    for i, x in enumerate(numbers):
        while stack and numbers[stack[-1]] < x:
            answer[stack.pop()] = x           # x 가 기다리던 숫자의 답
        stack.append(i)
    return answer
```

방향이 반대다. 새 숫자 `x` 가 오면, 기다리던 숫자들 중 `x` 보다 작은 것들이 **한꺼번에** 답을 얻는다.

- 답을 넣을 자리를 알아야 하니 값 대신 **위치(인덱스)** 를 쌓는다
- `answer` 를 처음부터 `-1` 로 채워 두면 끝까지 답을 못 얻은 칸은 저절로 `-1` 이다. `else` 도, 마지막 뒤집기도 필요 없다
- `numbers` 를 건드리지 않는다. 통과한 코드는 `numbers.pop()` 으로 입력을 비운다

무작위 20,000건에서 통과한 코드와 결과가 같았다. 둘 다 O(n).

### 2. 만약 버리는 조건을 `while` 에 합친다면

```python
for x in reversed(numbers):
    while stack and stack[-1] <= x:
        stack.pop()
    answer.append(stack[-1] if stack else -1)
    stack.append(x)
```

통과한 코드와 같은 방향, 같은 동작이다. "버릴 동안 버린다" 를 `while` 조건에 넣으면 `break` 와 `else` 가 사라진다.
반복이 끝나면 스택 맨 위가 곧 답이고, 비었으면 `-1` 이다.

| 방식 | 도는 방향 | 스택에 쌓는 것 | 뒤집기 | 입력 훼손 |
|---|---|---|---|---|
| 통과한 코드 | 뒤에서부터 | 값 (답의 후보) | 필요 | 있음 (`pop`) |
| 앞에서부터 + 위치 | 앞에서부터 | 위치 (답을 기다리는 숫자) | 없음 | 없음 |

## 배운 것

1. **버린 것을 다시 볼 일이 없으면, 복사하지 말고 하나를 끝까지 들고 간다.** 복사는 그 자체로 O(n) 이라 숫자마다 하면 O(n²) 이다
2. **도는 방향을 바꾸면 버려도 되는 것이 생긴다.** 뒤에서부터 보면 지금 숫자보다 작거나 같은 후보는 영원히 쓸모없다
3. 안쪽 `while` 이 있어도 원소마다 **한 번 들어가고 한 번 빠지면** 전체는 O(n) 이다
4. "끝까지 찾았는데 없었다" 는 반복문의 `else` 에. `break` 없이 끝났을 때만 실행된다
5. 메서드는 괄호까지 써야 실행된다. `answer.reverse` 는 에러 없이 아무 일도 하지 않는다
