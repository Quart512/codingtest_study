## 무엇을 틀렸나

### 1. 실행조차 안 된 세 줄 — 메서드 이름, 대입 방향, `insert` 의 인자

```python
numbers.revert()                 # AttributeError: 'list' object has no attribute 'revert'
numbers[:]=numberss              # NameError: name 'numberss' is not defined
answer.insert(numbers[0])        # TypeError: insert expected 2 arguments, got 1
```

- 뒤집기는 `reverse()` 다
- 대입은 **왼쪽이 받는 쪽**이다. `numbers[:] = numberss` 는 아직 없는 `numberss` 를 읽어서 `numbers` 의 내용을 덮어쓰려는 문장이다
- `insert` 는 **위치와 값** 두 개를 받는다. 뒤에 붙이는 건 `append`

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

```python
numbers.reverse()
numberss=numbers[:]
answer.append(numberss[-1])
```

### 2. 보는 쪽(`[0]`)과 빼는 쪽(`pop()`)이 달랐다

```python
if numberss[0]>numbers[0]:       # 맨 앞을 본다
    ...
else:
    numberss.pop()               # 맨 뒤를 뺀다
```

리스트를 뒤집어 놓고 `pop()` 으로 한 칸씩 넘어가는 설계였다. `pop()` 은 **맨 뒤**를 빼므로 지금 볼 숫자도 맨 뒤(`[-1]`)에 있다.
`[0]` 은 아무리 `pop()` 을 해도 바뀌지 않는다.

같이 고친 것: 큰 수를 찾았을 때 넣는 값. `numbers[-1]`(지금 숫자)이 아니라 `numberss[-1]`(찾은 큰 수)이다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

```python
if numberss[-1]>numbers[-1]:
    answer.append(numberss[-1])
```

→ `pop()` 으로 줄여 가는 리스트는 **`[-1]` 로 본다.** 보는 끝과 빼는 끝을 맞춘다.

### 3. `-1` 을 넣는 자리 — `while` 안에 두면 건너뛸 때마다 들어간다

```python
while numberss:
    if numberss[-1]>numbers[-1]:
        answer.append(numberss[-1])
        break
    else:
        numberss.pop()
    answer.append(-1)            # 숫자 하나를 건너뛸 때마다 실행된다
```

```
solution([2, 3, 3, 5])  ->  [-1, 3, -1, -1, 5, -1, 5, -1]      (정답은 [3, 5, 5, -1])
```

`-1` 은 "끝까지 봤는데 없었다" 일 때 **한 번만** 들어가야 한다. 그 전 시도에서는 반대로 반복문 전체가 끝난 뒤 맨 밖에 한 번만 두었다.

**왜 그렇게 생각했나**

`while` 에 `else` 를 붙일 수 있는지 몰랐다.

**해결**

```python
while numberss:
    if numberss[-1]>numbers[-1]:
        answer.append(numberss[-1])
        break
    else:
        numberss.pop()
else:                            # while 의 짝. break 없이 끝났을 때만
    answer.append(-1)
```

→ "끝까지 찾았는데 없었다" 는 반복문의 `else` 에 적는다. [[반복문의 else]]

### 4. 시간 초과

```python
def solution(numbers):
    answer = []
    numbers.reverse()
    while numbers:
        numberss=numbers[:]
        while numberss:
            if numberss[-1]>numbers[-1]:
                answer.append(numberss[-1])
                break
            else:
                numberss.pop()
        else:
            answer.append(-1)
        numbers.pop()

    return answer
```

1–3번을 고친 코드. 제출하면 시간 초과가 난다. 어느 테스트가 실패했는지는 기록하지 못했다.

**관찰**

- **답은 맞다.** 공식 예제 2개와, 이중 반복문으로 짠 풀이와 비교한 무작위 20,000건이 전부 일치한다
- 복사본에 지금 숫자 자신이 들어 있지만 문제없다. 조건이 `>` 라서 자기 자신은 큰 수가 될 수 없고, `pop()` 으로 빠진 뒤 다음으로 넘어간다
- 느린 건 입력 모양과 상관없다. 로컬에서 잰 시간:

| 길이 | 내림차순 (뒤에 큰 수가 없음) | 오름차순 (바로 뒤가 큰 수) |
|---|---|---|
| 5,000 | 0.39s | 0.010s |
| 10,000 | 1.54s | 0.042s |
| 20,000 | 6.32s | 0.175s |
| 40,000 | 25.97s | 0.728s |

- 두 경우 모두 길이가 2배가 될 때마다 시간이 약 4배 → **O(n²)**
- 오름차순은 첫 비교에서 바로 답을 찾는데도 4배씩 늘어난다. **찾기 전에 `numbers[:]` 로 뒤 전체를 복사하는 것만으로 이미 O(n)** 이기 때문이다. 숫자마다 한 번씩 복사하니 n × n
- 숫자는 최대 1,000,000개. 이 방식은 다듬어서 될 문제가 아니다

**왜 그렇게 생각했나**

시간 초과가 날 걸 알고 일부러 먼저 만들었다. 느린 버전을 끝까지 맞게 만들어 두고, 그다음 풀이에서 무엇이 바뀌는지 비교하려고.
