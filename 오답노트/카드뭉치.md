# 카드뭉치

- 문제: [프로그래머스 159994 - 카드 뭉치](https://school.programmers.co.kr/learn/courses/30/lessons/159994)
- **코드: [코드/카드뭉치.py](../코드/카드뭉치.py)** ← 통과시킨 코드 원본

> [!info] 이 노트의 역할
> `.py` 에는 실제로 통과시킨 코드만 담백하게 둔다 (테스트 코드의 주석은 예외).
> 설명, 주석, 대안 풀이는 전부 이 노트에 적는다. 코드 파일은 기록, 노트는 회고.

## 무엇을 틀렸나

### 1. `and` 의 평가 순서

```python
if cards1[0] == goal[0] and cards1:
```

`IndexError: list index out of range`

**왜 그렇게 생각했나**
"`cards1` 이 비어 있으면 조건 전체가 어차피 False 니까 순서는 상관없겠지."

→ 틀렸다. 파이썬은 조건을 다 계산한 뒤 판단하지 않는다. **왼쪽부터 하나씩 계산하다가 결론이 나면 멈춘다** (단락 평가, short-circuit).
그래서 `cards1` 이 비었는지 확인하기 **전에** 이미 `cards1[0]` 을 꺼내려 하고, 뭉치 하나가 먼저 바닥나는 입력에서 터진다.
안전장치를 안 넣은 게 아니라, 안전장치를 **아무 일도 못 하는 자리**에 놓았던 것.

**해결**

```python
if cards1 and cards1[0] == goal[0]:
```

`A and B` 에서 **B가 안전하려면 A가 B의 방패 역할을 해야 한다.** 순서가 곧 보호 장치다.
자세히: [[IndexError - list index out of range]]

### 2. 반환 타입

```python
answer = True
...
answer = False
```

**왜 그렇게 생각했나**
"가능한가?" 를 묻는 문제라 당연히 불리언이라고 생각하고 문제의 반환 형식을 다시 안 봤다.

**해결**

```python
answer = "Yes"
...
answer = "No"
```

이 문제는 문자열 `"Yes"` / `"No"` 를 요구한다. 로직이 전부 맞아도 여기서 오답 처리된다.

## 이렇게 했으면 어땠을까

### 1. 만약 빼지 않는 방식으로 한다면

제출한 `pop(0)` 풀이가 틀린 건 아니다. 다만 이 문제는 꺼낸 카드를 다시 쓰지 않으므로, **뺄 필요 없이 어디까지 읽었는지만 기억**하는 방식도 가능하다.

```python
def solution(cards1, cards2, goal):
    i = j = 0
    for word in goal:
        if i < len(cards1) and cards1[i] == word:
            i += 1
        elif j < len(cards2) and cards2[j] == word:
            j += 1
        else:
            return "No"
    return "Yes"
```

이렇게 하면 부수적으로 세 가지가 따라온다.

- `while goal:` + `pop` 대신 `for word in goal` 이라 **종료 조건을 신경 쓸 필요가 없다**
- 원본 리스트를 건드리지 않아 **같은 입력으로 다시 테스트할 수 있다** (지금 `.py` 는 테스트마다 `cards1[:]` 로 복사본을 넘긴다)
- 범위 검사 `i < len(cards1)` 가 조건에 자연스럽게 들어가서 **1번 실수가 애초에 나올 수 없다**

세 번째가 핵심이다. `and` 순서를 고쳐서 버그를 막을 수도 있지만, **버그가 날 수 없는 구조를 고르는 쪽**이 더 확실하다.

### 2. 굳이 뺀다면 deque

앞에서 빼는 게 정말 필요한 문제였다면 `list` 가 아니라 `deque` 다.

```python
from collections import deque
cards1, cards2, goal = deque(cards1), deque(cards2), deque(goal)
# cards1.popleft() -> O(1)
```

단, **이 문제에서는 과하다.** 카드가 최대 10장이라 `pop(0)` 의 O(n²) 이 전혀 문제가 안 된다.
`deque` 는 n이 10만쯤 되어 `list` 로는 시간 초과가 날 때 꺼내는 카드다.

| 방식 | 시간복잡도 | 원본 훼손 | 언제 |
|---|---|---|---|
| `list.pop(0)` — 제출한 풀이 | O(n²) | 있음 | n이 작을 때 |
| `deque.popleft()` | O(n) | 있음 | 앞에서 실제로 빼야 하고 n이 클 때 |
| 인덱스 포인터 | O(n) | 없음 | 빼지 않고 읽기만 하면 될 때 |

→ 판단 기준은 [[앞에서 빼야 할 때]], 패턴 자체는 [[두 뭉치 순서대로 꺼내기]]

## 배운 것

1. `and` / `or` 는 **왼쪽부터** 평가된다. 범위 검사는 항상 **왼쪽**에.
2. 반환 타입(문자열/불리언)을 문제에서 다시 확인할 것.
3. "앞에서 빼는 문제"처럼 보여도 실은 **읽기만** 하면 되는 경우가 많다.
4. 원소 중복이 없다는 조건이 있으면 선택지가 하나뿐이라 **그리디로 충분**하다.
