# 카드뭉치

- 문제: [프로그래머스 159994 - 카드 뭉치](https://school.programmers.co.kr/learn/courses/30/lessons/159994)
- **코드: [코드/카드뭉치.py](../코드/카드뭉치.py)** ← 세 가지 풀이 + 테스트. 이 파일이 원본이다

> [!info] 이 노트의 역할
> 코드는 `.py` 파일 하나에만 둔다. 여기에는 **무엇을 왜 틀렸는지**만 적는다.
> 코드를 보려면 위 링크를 클릭 (VSCode Editor 플러그인이 옵시디언 안에서 열어준다).

## 무엇을 틀렸나

`IndexError: list index out of range`

```python
if cards1[0] == goal[0] and cards1:   # 틀림
if cards1 and cards1[0] == goal[0]:   # 맞음
```

`and` 는 **왼쪽부터** 평가된다. 첫 줄은 `cards1` 이 비었는지 확인하기 **전에** 이미 `cards1[0]` 을 꺼내려 하므로, 뭉치 하나가 먼저 바닥나는 입력에서 터진다.

안전장치를 안 넣은 게 아니라, 안전장치를 **아무 일도 못 하는 자리**에 놓았던 것.

## 왜 그렇게 생각했나

"`cards1` 이 비어 있으면 조건 전체가 어차피 False 니까 순서는 상관없겠지."

→ 틀렸다. 파이썬은 조건을 **다 계산한 뒤 판단하는 게 아니라, 왼쪽부터 하나씩 계산하다가 결론이 나면 멈춘다** (단락 평가, short-circuit).
그래서 `A and B` 에서 **B가 안전하려면 A가 B의 방패 역할을 해야 한다.** 순서가 곧 보호 장치다.

자세히: [[IndexError - list index out of range]]

> [!note] 반환값 함정
> 이 문제는 `True` / `False` 가 아니라 문자열 `"Yes"` / `"No"` 를 돌려줘야 한다. 로직이 맞아도 여기서 오답 처리된다.

## 세 가지 풀이 비교

| 함수 (`코드/카드뭉치.py`) | 방식 | 시간복잡도 | 원본 훼손 |
|---|---|---|---|
| `solution_pop` | `list.pop(0)` — 실제 제출한 풀이 | O(n²) | 있음 |
| `solution_deque` | `deque.popleft()` | O(n) | 있음 (복사본) |
| `solution_pointer` | 인덱스 이동 — **기본으로 삼을 것** | O(n) | 없음 |

카드가 최대 10장이라 셋 다 통과한다. **성능 차이 때문이 아니라 습관 때문에** 포인터 방식을 기본으로 둔다.
핵심 아이디어: 빼는 대신 **어디까지 읽었는지만 기억**하면 자료구조 변환도, 원소 이동도 필요 없다.

→ 판단 기준은 [[앞에서 빼야 할 때]], 패턴 자체는 [[두 뭉치 순서대로 꺼내기]]

## 배운 것

1. `and` / `or` 는 **왼쪽부터** 평가된다. 범위 검사는 항상 **왼쪽**에.
2. "앞에서 빼는 문제"처럼 보여도 실은 **읽기만** 하면 되는 경우가 많다.
3. 원소 중복이 없다는 조건이 있으면 선택지가 하나뿐이라 **그리디로 충분**하다.
4. 반환 타입(문자열/불리언)을 문제에서 다시 확인할 것.

## 다시 풀 때 체크

- [ ] 반환 타입이 문제 요구와 같은가
- [ ] 한쪽 뭉치가 먼저 바닥나는 입력을 넣어봤는가 (`["a"], ["b"], ["a","b","c"]`)
