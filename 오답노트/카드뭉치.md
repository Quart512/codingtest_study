# 카드뭉치

- 문제: [프로그래머스 159994 - 카드 뭉치](https://school.programmers.co.kr/learn/courses/30/lessons/159994)
- **코드: [코드/카드뭉치.py](../코드/카드뭉치.py)** ← 세 가지 풀이 + 테스트. 이 파일이 원본이다

> [!info] 이 노트의 역할
> `.py` 에는 **실제로 통과시킨 코드만** 담백하게 둔다 (테스트 코드의 주석은 예외).
> 설명, 주석, 대안 풀이는 전부 이 노트에 **"이렇게 했으면 어땠을까"** 로 적는다.
> 코드 파일은 기록, 노트는 회고.

## 무엇을 틀렸나

`IndexError: list index out of range`

```python
if cards1[0] == goal[0] and cards1:   # 틀림
if cards1 and cards1[0] == goal[0]:   # 맞음
```

`and` 는 **왼쪽부터** 평가된다. 첫 줄은 `cards1` 이 비었는지 확인하기 **전에** 이미 `cards1[0]` 을 꺼내려 하므로, 뭉치 하나가 먼저 바닥나는 입력에서 터진다.

안전장치를 안 넣은 게 아니라, 안전장치를 **아무 일도 못 하는 자리**에 놓았던 것.

## 왜 그렇게 생각했나

"`cards1` 이 비어 있으면 조건 전체가 어차피 False 니까 순서는 상관없겠지."

→ 틀렸다. 파이썬은 조건을 **다 계산한 뒤 판단하는 게 아니라, 왼쪽부터 하나씩 계산하다가 결론이 나면 멈춘다** (단락 평가, short-circuit).
그래서 `A and B` 에서 **B가 안전하려면 A가 B의 방패 역할을 해야 한다.** 순서가 곧 보호 장치다.

자세히: [[IndexError - list index out of range]]

> [!note] 반환값 함정
> 이 문제는 `True` / `False` 가 아니라 문자열 `"Yes"` / `"No"` 를 돌려줘야 한다. 로직이 맞아도 여기서 오답 처리된다.

## 이렇게 했으면 어땠을까

### 1. 애초에 빼지 말았어야 했다

`pop(0)` 으로 뺄 생각부터 한 게 출발점이 틀렸다. 이 문제는 꺼낸 카드를 다시 쓰지 않는다.
그러면 **뺄 필요 없이 어디까지 읽었는지만 기억**하면 된다.

```python
def solution(cards1, cards2, goal):
    i = j = 0
    for word in goal:
        if i < len(cards1) and cards1[i] == word:
            i += 1
        elif j < len(cards2) and cards2[j] == word:
            j += 1
        else:
            return "No"
    return "Yes"
```

이렇게 하면 부수적으로 세 가지가 같이 해결된다.

- `while goal:` + `pop` 대신 `for word in goal` 이라 **종료 조건을 신경 쓸 필요가 없다**
- 원본 리스트를 건드리지 않아 **같은 입력으로 다시 테스트할 수 있다** (지금 `.py` 는 테스트마다 `cards1[:]` 로 복사본을 넘겨야 한다)
- 범위 검사 `i < len(cards1)` 가 조건에 자연스럽게 들어가서 **IndexError 가 애초에 안 난다**

세 번째가 핵심이다. 내가 낸 버그는 `and` 순서를 고쳐서 막은 게 아니라, **버그가 날 수 없는 구조로 바꿨으면 막을 수 있었던 것**이다.

### 2. 굳이 뺀다면 deque

앞에서 빼는 게 정말 필요한 문제였다면 `list` 가 아니라 `deque` 였다.

```python
from collections import deque
cards1, cards2, goal = deque(cards1), deque(cards2), deque(goal)
# cards1.popleft() -> O(1)
```

단, **이 문제에서는 오버엔지니어링이다.** 카드가 최대 10장이라 `pop(0)` 의 O(n²) 이 전혀 문제가 안 된다.
`deque` 는 n이 10만쯤 되어 `list` 로는 시간 초과가 날 때 꺼내는 카드다.

| 방식 | 시간복잡도 | 원본 훼손 | 언제 |
|---|---|---|---|
| `list.pop(0)` — 제출한 풀이 | O(n²) | 있음 | n이 작을 때 |
| `deque.popleft()` | O(n) | 있음 | 앞에서 실제로 빼야 하고 n이 클 때 |
| 인덱스 포인터 | O(n) | 없음 | 빼지 않고 읽기만 하면 될 때 — **기본** |

→ 판단 기준은 [[앞에서 빼야 할 때]], 패턴 자체는 [[두 뭉치 순서대로 꺼내기]]

## 배운 것

1. `and` / `or` 는 **왼쪽부터** 평가된다. 범위 검사는 항상 **왼쪽**에.
2. "앞에서 빼는 문제"처럼 보여도 실은 **읽기만** 하면 되는 경우가 많다.
3. 원소 중복이 없다는 조건이 있으면 선택지가 하나뿐이라 **그리디로 충분**하다.
4. 반환 타입(문자열/불리언)을 문제에서 다시 확인할 것.
