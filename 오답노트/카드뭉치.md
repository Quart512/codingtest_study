# 카드 뭉치

- 문제: [프로그래머스 159994 - 카드 뭉치](https://school.programmers.co.kr/learn/courses/30/lessons/159994)
- 코드: [카드뭉치.py](../코드/카드뭉치.py)

## 무엇을 틀렸나

`IndexError: list index out of range`

```python
if cards1[0] == goal[0] and cards1:   # 여기
```

`and` 는 **왼쪽부터** 평가한다. `cards1` 이 비었는지 확인하기 **전에** 이미 `cards1[0]` 을 꺼내려 하므로,
뭉치 하나가 먼저 바닥나는 입력에서 터진다.

`and` 오른쪽에 안전장치를 둔 게 아니라, 안전장치가 **아무 일도 못 하는 자리**에 놓여 있었던 것.

## 왜 그렇게 생각했나

"`cards1` 이 비어 있으면 어차피 False 니까 순서는 상관없겠지" 라고 생각했다.
→ 틀렸다. **파이썬은 조건을 다 계산한 뒤 판단하는 게 아니라, 왼쪽부터 하나씩 계산하다가 결론이 나면 멈춘다** (단락 평가, short-circuit).
따라서 `A and B` 에서 **B가 안전하려면 A가 B의 방패 역할을 해야 한다.**

자세히: [[IndexError - list index out of range]]

## 고친 풀이

```python
def solution(cards1, cards2, goal):
    answer = "Yes"
    while goal:
        if cards1 and cards1[0] == goal[0]:      # 존재 확인 -> 값 비교
            cards1.pop(0)
            goal.pop(0)
        elif cards2 and cards2[0] == goal[0]:
            cards2.pop(0)
            goal.pop(0)
        else:
            answer = "No"
            break
    return answer
```

> [!note] 반환값 함정
> 이 문제는 `True` / `False` 가 아니라 문자열 `"Yes"` / `"No"` 를 돌려줘야 한다. 로직이 맞아도 여기서 오답 처리된다.

## 더 나은 풀이

빼는 대신 **어디까지 읽었는지만 기억**하면 된다. 자료구조 변환도, 원소 이동도 없다.

```python
def solution(cards1, cards2, goal):
    i = j = 0
    for word in goal:
        if i < len(cards1) and cards1[i] == word:
            i += 1
        elif j < len(cards2) and cards2[j] == word:
            j += 1
        else:
            return "No"
    return "Yes"
```

| 풀이 | 시간복잡도 | 원본 훼손 |
|---|---|---|
| `list.pop(0)` | O(n²) | 있음 |
| `deque.popleft()` | O(n) | 있음 (복사본) |
| 인덱스 포인터 | O(n) | 없음 |

세 가지 모두 [카드뭉치.py](../코드/카드뭉치.py) 에 구현해 두고 테스트로 검증했다.
카드가 최대 10장이라 이 문제에서는 셋 다 통과한다. **성능 차이가 아니라 습관을 위해** 포인터 방식을 기본으로 삼는다.

## 배운 것

1. `and` / `or` 는 **왼쪽부터** 평가된다. 범위 검사는 항상 **왼쪽**에.
2. "앞에서 빼는 문제"처럼 보여도 실은 **읽기만** 하면 되는 경우가 많다. → [[앞에서 빼야 할 때]]
3. 중복 없는 원소 조건이 있으면 선택지가 하나뿐이라 **그리디로 충분**하다. → [[두 뭉치 순서대로 꺼내기]]
4. 반환 타입(문자열/불리언)을 문제에서 다시 확인할 것.
