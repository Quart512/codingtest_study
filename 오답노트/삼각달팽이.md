## 무엇을 틀렸나

### 1. 위치 공식으로 규칙을 하나씩 추가 — n이 커지면 규칙이 끝없이 늘어난다

```python
for i in range(n):
    full_dict[int(i*(i+1)/2)+1]=i+1          # 왼쪽 변
    full_dict[int(n*(n-1)/2)+i+1]=n+i        # 아래 변
```

1차원 dict(키 = 위에서부터 센 칸 번호)에, 각 변에 들어갈 숫자를 **위치 공식으로 직접** 넣었다.
두 공식 자체는 맞다. n=6 으로 돌리면 바깥 껍질의 두 변이 정확히 채워진다.

```
      1
      2   0
      3   0   0
      4   0   0   0
      5   0   0   0   0
      6   7   8   9  10  11
```

그런데 오른쪽 변까지 넣으면 껍질 한 겹이 끝나고, **안쪽에 더 작은 삼각형이 또 생긴다.**
그 삼각형에도 세 변이 있고, 그 안에 또 삼각형이 있다.
껍질 수는 약 n/3 이라 **n이 커지면 필요한 공식 수도 같이 늘어난다.** 고정된 코드로는 끝낼 수 없다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

각 숫자의 위치를 공식으로 계산하지 않고, **한 칸씩 걸어가며** 방향만 바꾼다.
방향은 `왼쪽 아래 → 오른쪽 → 왼쪽 위` 3개로 고정이라, n이 뭐든 규칙 수가 늘지 않는다.

→ 규칙 수가 입력 크기에 따라 늘어나면, 공식이 아니라 **반복되는 동작**을 찾는다.

### 2. 방향 전환 방식 — 정답은 맞는데 시간 초과

1번의 해결대로 방향 3개를 함수로 만들고, 다리 길이만큼 걷게 했다.

```python
def solution(n):
    answer = []
    full_list = [i+1 for i in range(int(n*(n+1)/2))]
    full_dict = {i: 0 for i in full_list}
    full_dict_layer = {i: 0 for i in full_list}

    for i in range(n):
        for block in full_list:
            if int(i*(i+1)/2)<block:
                full_dict_layer[block] += 1

    def left_down(now):
        now_layer = full_dict_layer[now]
        return now+now_layer
    def right(now):
        return now+1
    def left_up(now):
        now_layer = full_dict_layer[now]
        return now - now_layer

    def turn(direction):
        if direction == left_down:
            return right
        if direction == right:
            return left_up
        if direction == left_up:
            return left_down

    direction_list=[]
    for i in range(n):
        direction_list.insert(i,n-i)
    direction_list[0]-=1
    direction_list.insert(-1,1)

    target=1
    num=1
    direction_now=left_down
    for moves in direction_list:
        for move in range(moves):
            full_dict[target]=num
            num+=1
            target = direction_now(target)
        direction_now = turn(direction_now)

    return  [v for v in full_dict.values()]
```

몇 개는 통과했고, 뒤쪽 테스트에서 시간 초과.

**관찰**

- **정답은 맞다.** n=1~5 전부 기대값과 일치. 틀린 답이 아니라 속도 문제다
- `full_dict_layer[칸]` = 그 칸의 **행 번호**(1부터). 아래로 가면 `+행번호`, 왼쪽 위로 가면 `-행번호` 가 되는 원리
- 다리 길이는 `[n-1, n-1, n-2, ..., 2, 1, 1]`. **기록 → 이동** 순서라 다리마다 마지막 이동이 한 칸 넘어가서, 첫 다리를 1 줄이고 끝에 1을 붙여 맞췄다

로컬에서 잰 실행 시간 (문제 조건 n ≤ 1000):

| n | 시간 | n 배율 | 시간 배율 |
|---|---|---|---|
| 100 | 0.04s | | |
| 300 | 1.0s | ×3 | ×25 |
| 600 | 8.4s | ×2 | ×8.4 |
| 1000 | 40.3s | ×1.7 | ×4.8 |

- n이 2배 → 시간 약 8배(2³), n이 1.7배 → 약 4.8배(1.7³ ≈ 4.6). **O(n³)** 로 늘고 있다
- 칸 수 자체가 n²/2 개라 답을 채우는 데만 O(n²) 는 어쩔 수 없다. **n이 하나 더 곱해진 곳**이 어딘가에 있다

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

느린 곳은 맨 위, 행 번호를 적는 이중 반복문이었다.

```python
for i in range(n):              # n번
    for block in full_list:     # × 칸 수(약 n²/2)번
        if int(i*(i+1)/2)<block:
            full_dict_layer[block] += 1
```

**n × n²/2 = O(n³).** 칸 하나의 행 번호를 알아내려고 매번 모든 행(n개)을 확인하고 있었다.
나눠서 재 보면 n=300 에서 이 부분이 1.2초, 칸을 걸어가는 부분은 0.003초. 느린 건 거의 전부 여기였다.

칸을 1번부터 순서대로 따라가면서 **"지금 몇 행째인지"만 기억**하면, 칸마다 한 번씩만 적으면 된다.

```python
now_layer=1
for block in full_list:
    if int(now_layer*(now_layer+1)/2)<block:
        now_layer+=1
    full_dict_layer[block]=now_layer
```

칸 수만큼만 돌므로 **O(n²).** 칸마다 숫자를 하나씩은 적어야 하니 이보다 줄일 수는 없다.

| n | 고치기 전 | 고친 후 |
|---|---|---|
| 300 | 1.0s | 0.010s |
| 600 | 8.4s | 0.043s |
| 1000 | 40.3s | 0.121s |

→ 반복문 안에 반복문이 있으면 **바깥 × 안쪽**을 곱하고, 문제의 입력 제한(n ≤ 1000)을 넣어 본다. 10억이 나오면 그 방식은 버린다. [[시간복잡도]]

### 3. 행 번호 반복문을 고쳤더니 — 행의 첫 칸이 0으로 남았다

2번을 고치려고 처음 짠 반복문:

```python
now_layer=1
for block in full_list:
    if int(now_layer*(now_layer+1)/2)>=block:
        full_dict_layer[block] =now_layer
    else:
        now_layer+=1
```

n=4 로 돌리면:

```
{1: 1, 2: 0, 3: 2, 4: 0, 5: 3, 6: 3, 7: 0, 8: 4, 9: 4, 10: 4}
```

2, 4, 7 — **각 행이 시작되는 칸**만 0이다.
`else` 로 가는 칸이 바로 새 행의 첫 칸인데, 거기서 `now_layer` 만 올리고 **그 칸에는 아무것도 적지 않았다.**
행 번호가 0인 칸에서 `left_down` 을 하면 `now + 0` 이라 제자리에 멈춘다.

**왜 그렇게 생각했나**

<!-- 이 방식으로 짤 때 머릿속에 있던 전제를 적을 것 -->

**해결**

"행을 넘어갔으면 먼저 올리고, 칸에는 **항상** 적는다" 로 순서를 바꾼다.

```python
    if int(now_layer*(now_layer+1)/2)<block:
        now_layer+=1
    full_dict_layer[block]=now_layer      # if 밖으로 — 모든 칸이 지나감
```

→ **상태를 바꾸는 일**과 **기록하는 일**을 `if / else` 로 갈라 놓으면, 한쪽 길로 간 칸은 기록이 빠진다. 기록은 분기 밖에 둔다.

같이 뺀 것: 디버깅용 `print(full_dict_layer)`. n=1000 이면 50만 개짜리 dict 를 출력하게 되어 그것만으로도 느려질 수 있다.

## 이렇게 했으면 어땠을까

### 1. 만약 삼각형 모양 그대로 2차원 리스트로 잡는다면

```python
def solution(n):
    tri = [[0] * (i + 1) for i in range(n)]    # 0행 1칸, 1행 2칸, ...
    r, c, num = -1, 0, 1
    for i in range(n):
        for _ in range(n - i):
            if i % 3 == 0:   r += 1            # 아래로
            elif i % 3 == 1: c += 1            # 오른쪽
            else:            r -= 1; c -= 1    # 왼쪽 위
            tri[r][c] = num
            num += 1
    return [x for row in tri for x in row]
```

- 칸을 **(행, 열) 좌표**로 바로 가리키니 "이 칸이 몇 행인가" 를 계산할 필요가 없다.
  `full_dict_layer` 가 통째로 사라지고, **2번(O(n³))과 3번(첫 칸 0) 실수가 애초에 생길 자리가 없다**
- 1차원 칸 번호로 삼각형을 다루려면 "아래로 = +행번호" 같은 **변환 공식**이 필요하다. 자료구조를 문제의 모양대로 잡으면 그 변환이 없어진다

### 2. 만약 이동 → 기록 순서로 한다면

지금 코드는 **기록 → 이동** 순서라 다리마다 마지막 이동이 한 칸 넘어간다.
그래서 다리 길이를 `[n-1, n-1, n-2, ..., 2, 1, 1]` 로 보정했다.

시작점을 한 칸 밖(`r = -1`)에 두고 **이동 → 기록**으로 하면 다리 길이가 `n, n-1, ..., 1` 그대로다.
보정도, 첫 다리 예외도 필요 없다. 위 1번 코드가 이 방식이다.

| 방식 | 시간복잡도 | 행 번호 계산 | 다리 길이 보정 |
|---|---|---|---|
| 통과한 코드 (1차원 dict, 기록 → 이동) | O(n²) | 필요 | 필요 |
| 2차원 리스트, 이동 → 기록 | O(n²) | 없음 | 없음 |

## 배운 것

1. 입력이 커질수록 필요한 규칙 수가 늘어나면, 위치 공식이 아니라 **반복되는 동작**(방향 3개)을 찾는다
2. 반복문 안에 반복문 → **바깥 × 안쪽**을 곱하고 입력 제한을 넣어 본다. n ≤ 1000 에서 O(n³) = 10억은 안 된다
3. 상태 갱신과 기록을 `if / else` 로 가르지 않는다. **기록은 분기 밖에서 항상**
