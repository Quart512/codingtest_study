# heapq

## 무엇인가

**가장 작은 값을 빠르게 꺼내기 위한 자료구조**(힙, heap)와 그것을 다루는 파이썬 표준 모듈.

넣을 때마다 조금씩 정리해 두고, 꺼낼 때 맨 앞에서 바로 가져간다.
정렬과의 차이가 핵심이다. **힙은 전체를 정렬하지 않는다.**

## 힙이 지키는 규칙은 하나뿐

**부모는 자식보다 작다.** 형제끼리의 순서는 정해져 있지 않다.

```python
[5, 3, 8, 1, 9, 2] 을 차례로 push 하면 -> [1, 3, 2, 5, 9, 8]
```

```
        1
      /   \
     3     2
    / \   /
   5   9 8
```

부모-자식은 모두 작은 쪽이 위에 있지만, `3` 이 `2` 보다 큰 건 상관없다. 둘은 형제가 아니라 다른 가지다.

그래서

- `h[0]` 은 **항상 최솟값**이다
- `h[1]` 은 **두 번째로 작은 값이 아니다.** 두 번째를 알려면 `heappop` 해야 한다
- 힙 리스트를 그냥 출력하면 뒤죽박죽으로 보인다. 정상이다

**정렬을 포기한 대가로 빠르다.**

## 어떻게 동작하나

리스트 하나로 이진 트리를 표현한다. 포인터 없이 **인덱스 계산**만으로 부모·자식을 찾는다.

```
i 의 자식 -> 2i+1, 2i+2
i 의 부모 -> (i-1)//2
```

- **push**: 맨 뒤에 붙인 뒤, 부모와 비교해 작으면 자리를 바꾸며 **위로 올라간다**
- **pop**: 뿌리(최솟값)를 빼고, 맨 뒤 원소를 뿌리로 올린 뒤 자식과 비교하며 **내려간다**

둘 다 **트리 높이만큼만** 비교한다. 원소가 n개면 높이는 약 log₂n 이므로 **O(log n)**.
100만 개여도 20번 남짓이다.

## 파이썬에서: heapq

파이썬에는 힙 자료형이 따로 없다. **평범한 리스트를 힙 규칙에 맞게 다뤄 주는 함수들**이 있을 뿐이다.

```python
import heapq

h = []
heapq.heappush(h, 3)      # 넣기            O(log n)
heapq.heappop(h)          # 최솟값 빼기      O(log n)
h[0]                      # 빼지 않고 보기   O(1)
len(h)                    # 개수            O(1)

lst = [5, 3, 8, 1]
heapq.heapify(lst)        # 기존 리스트를 제자리에서 힙으로. O(n)
```

`heapify` 는 하나씩 `heappush` 하는 것(O(n log n))보다 빠르다. 처음부터 리스트가 있다면 이쪽.

### 편의 함수

```python
heapq.heappushpop(h, x)   # 넣고 나서 빼기 (따로 부르는 것보다 빠름)
heapq.heapreplace(h, x)   # 빼고 나서 넣기
heapq.nlargest(k, data)   # 큰 것 k개, 내림차순
heapq.nsmallest(k, data)  # 작은 것 k개, 오름차순
```

> [!warning] nlargest / nsmallest 는 있는 만큼만 준다
> 원소가 k개보다 적으면 **k개가 아니라 있는 만큼** 돌려준다.
> `nlargest(3, [10])` 의 길이는 1이다. `[k-1]` 로 집으면 `IndexError`.
> 사례: [[명예의전당1]]

### 최대 힙이 필요하면 부호를 뒤집는다

파이썬 `heapq` 에는 **최소 힙밖에 없다.** 최댓값이 필요하면 넣을 때 음수로 바꾼다.

```python
heapq.heappush(h, -score)
largest = -heapq.heappop(h)
```

### 튜플로 우선순위 붙이기

튜플은 **앞 요소부터** 비교한다. 같으면 다음 요소로 넘어간다.

```python
heapq.heappush(h, (점수, 이름))     # 점수로 먼저, 같으면 이름으로
```

앞 요소가 같을 때 뒤 요소끼리 비교할 수 없는 타입(예: 사용자 객체)이면 `TypeError` 가 난다.
그럴 땐 `(점수, 순번, 객체)` 처럼 **절대 겹치지 않는 값**을 가운데 끼운다.

## list, 정렬과 비교

| | 넣기 | 최솟값 보기 | 최솟값 빼기 | 전체 순서 |
|---|---|---|---|---|
| 그냥 list + `min()` | O(1) | O(n) | O(n) | 없음 |
| 항상 정렬해 두기 | O(n) | O(1) | O(1) | 있음 |
| **heapq** | **O(log n)** | **O(1)** | **O(log n)** | **없음** |

- **넣기와 빼기가 번갈아 자주** 일어나면 힙이 이긴다
- 한 번 넣고 끝이면 `sorted()` 가 낫다. 힙은 중간중간 꺼낼 때 값어치가 있다
- 2등, 3등까지 순서대로 알아야 하면 힙은 맞지 않는다. 그건 정렬이다

## 자주 쓰는 패턴: 크기 k 를 유지한다

**상위 k개만 계속 알고 싶을 때.** 힙에 k개만 남기고 넘치면 버린다.

```python
h = []
for x in data:
    heapq.heappush(h, x)
    if len(h) > k:
        heapq.heappop(h)      # 최소 힙이므로 가장 작은 것이 버려진다
    # 이 시점에 h 는 '지금까지의 상위 k개', h[0] 은 그중 꼴찌 = k등
```

최소 힙인데 **상위** k개가 남는 게 헷갈릴 수 있다.
버려지는 게 항상 최솟값이므로, 살아남는 건 큰 값들이다. 그리고 `h[0]` 은 그 k개 중 가장 작은 값, 즉 **k등**이다.

원소가 아직 k개가 안 되면 아무것도 버리지 않고 `h[0]` 은 그때까지의 최솟값이 된다.
**경계를 따로 처리할 필요가 없다는 게 이 패턴의 장점이다.**

전체를 정렬(O(n log n))하지 않고 **O(n log k)** 로 끝난다. 사례: [[명예의전당1]]

## 주의할 점

- **힙 리스트를 직접 고치지 않는다.** `h[2] = 100`, `h.append(x)`, `h.sort()` 전부 규칙을 깬다. `heappush` / `heappop` 으로만 건드린다
- **빈 힙에 `heappop` 하면 `IndexError`.** 꺼내기 전에 `if h:` → [[IndexError - list index out of range]]
- `h[0]` 은 최솟값이지만 `h[-1]` 은 최댓값이 **아니다.** 힙이 보장하는 건 뿌리뿐이다
