# 해시

## 무엇인가

입력값(키)을 해시 함수에 넣어 고정 길이의 정수(해시값)로 바꾸고, 그 값을 배열의 인덱스처럼 써서 데이터에 **곧바로** 접근하는 방식.

리스트에서 값을 찾는 것과 비교하면 차이가 분명하다.

- **리스트**: 앞에서부터 하나씩 비교하며 찾아간다 → "찾아 헤맨다"
- **해시**: 키를 계산해서 저장 위치를 바로 알아낸다 → "계산해서 그 자리로 간다"

## 어떻게 동작하나

1. 키를 해시 함수에 넣어 정수(해시값)를 만든다
2. 그 값을 저장 공간의 크기로 나눈 나머지 등으로 **저장할 위치**를 정한다
3. 그 위치에 (키, 값)을 저장한다
4. 조회할 때도 같은 계산을 해서 저장했던 위치로 바로 찾아간다

서로 다른 키가 같은 위치로 계산되는 경우(충돌)는 그 위치에 여러 개를 함께 저장하는 방식 등으로 처리한다. 파이썬에서는 이 부분을 언어가 알아서 처리하므로 신경 쓸 필요 없다.

## 파이썬에서: dict, set

파이썬의 `dict` 와 `set` 은 내부적으로 해시 테이블로 구현되어 있다.

- **dict** — 키-값 쌍을 저장. 키로 값을 조회하면 O(1) 평균
- **set** — 값의 존재 여부만 저장. 존재 확인이 O(1) 평균

### dict 기본 사용법

```python
count = {}
count["a"] = 1              # 저장 - O(1)
count["a"] += 1             # 조회 후 수정 - O(1)

count["a"]                  # 조회 - O(1). 없는 키면 KeyError
count.get("b", 0)           # 없으면 기본값 반환, 에러 없음

"a" in count                # 키 존재 확인 - O(1)

for key in count:           # 키 순회
    ...
for key, value in count.items():   # 키, 값 함께 순회
    ...
```

### 값 → 위치를 미리 저장해두는 패턴

```python
index_of = {value: i for i, value in enumerate(lst)}
pos = index_of[target]      # O(1). list.index(target) 은 O(n)
```

### set 기본 사용법

```python
seen = set()
seen.add("a")                # 추가 - O(1)
"a" in seen                  # 존재 확인 - O(1)
seen.discard("a")            # 삭제, 없어도 에러 없음
```

### 개수 세기: collections.Counter

```python
from collections import Counter
cnt = Counter(["a", "b", "a", "c", "a"])
# Counter({'a': 3, 'b': 1, 'c': 1})
```

## list와 비교

| 연산 | list | dict / set |
|---|---|---|
| 값이 있는지 확인 (`x in obj`) | O(n) | O(1) 평균 |
| 값으로 위치 찾기 (`list.index(x)`) | O(n) | 애초에 값 → 대응값을 O(1)에 즉시 얻음 |
| 순서 유지 | 항상 유지 | dict는 파이썬 3.7+부터 입력 순서 유지, set은 순서 보장 안 됨 |
| 중복 | 허용 | dict/set의 키는 중복 불가 — 나중 값이 덮어씀 |
| 키로 쓸 수 있는 타입 | — | **해시 가능한(불변) 타입만.** 문자열·숫자·튜플은 가능, list는 불가능 |

## 왜 빨라지나

`list.index(x)` 는 앞에서부터 하나씩 비교한다. 원소가 n개면 최악의 경우 n번 비교해야 하므로 O(n).
`dict[x]` 는 x를 해시 함수에 넣어 저장 위치를 계산할 뿐이다. 원소가 몇 개든 계산은 한 번이므로 O(1) 평균.

**"값 → 위치를 미리 계산해 저장해 둔다"** 가 핵심이다. 매번 찾아 헤매는 대신, 필요할 때 그 자리로 바로 간다.
