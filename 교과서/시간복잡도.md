# 시간복잡도

## 무엇인가

**입력이 커질 때 작업 횟수가 어떤 모양으로 늘어나는가**를 나타낸 것.
몇 초가 걸리는지가 아니라, **n이 2배가 되면 작업이 몇 배가 되는가**를 본다.

- **n** = 입력 크기. 리스트 길이, 선수 수, 삼각형 한 변의 길이 등
- **O(...)** = 빅오(Big-O) 표기. 그 늘어나는 모양을 적는 방법

## 대표 모양

n = 1000 일 때 작업 횟수:

| 표기 | 이름 | n이 2배면 | n = 1000 | 대표 예 |
|---|---|---|---|---|
| O(1) | 상수 | 그대로 | 1 | `lst[3]`, `d[key]`, `x in set` |
| O(log n) | 로그 | +1번 | 약 10 | 이진 탐색 (매번 절반으로 줄임) |
| O(n) | 선형 | 2배 | 1,000 | `for x in lst`, `lst.index(x)`, `x in lst` |
| O(n log n) | | 약 2배 | 약 10,000 | `sorted(lst)`, `lst.sort()` |
| O(n²) | 제곱 | 4배 | 1,000,000 | 반복문 안에 반복문 |
| O(n³) | 세제곱 | 8배 | 1,000,000,000 | 반복문 3겹 |

n이 작을 땐 차이가 안 보이다가, 커지면 **자릿수가 달라진다.**

## 세는 법

### 규칙 1. 나란히 두면 더하고, 안에 넣으면 곱한다

```python
for x in A: ...          # n번
for y in B: ...          # n번
# 나란히 → n + n = 2n → O(n)

for x in A:
    for y in B: ...      # n번 × n번
# 안에 넣음 → n × n → O(n²)
```

반복 횟수가 n이 아닐 수도 있다. 바깥이 m번, 안쪽이 n번이면 **O(n × m)**.

### 규칙 2. 상수와 작은 항은 버린다

- `3n` → O(n). n이 2배면 3n도 2배. 모양이 같다
- `n²/2` → O(n²). n이 2배면 n²/2 도 4배
- `n² + n` → O(n²). n이 커지면 n² 에 비해 n은 무시할 만큼 작아진다

**늘어나는 모양만 본다.**

### 규칙 3. 함수 한 줄 안에 숨은 반복을 조심한다

코드상 `for` 가 하나뿐이어도, 안에서 부르는 함수가 **내부적으로 전체를 훑으면** 곱해진다.

```python
for c in callings:           # m번
    players.index(c)         #   × 매번 최대 n번 → O(n × m)
```

자주 숨어 있는 O(n) 연산:

| 연산 | 비용 | 왜 |
|---|---|---|
| `lst.index(x)`, `x in lst` | O(n) | 앞에서부터 하나씩 비교 |
| `lst.insert(0, x)`, `lst.pop(0)` | O(n) | 뒤 원소를 전부 한 칸씩 민다 |
| `lst[a:b]` 슬라이싱 | O(b-a) | 새 리스트로 복사 |
| `for k, v in d.items()` 로 값 찾기 | O(n) | dict 도 **값 → 키** 방향은 전체 스캔 |
| `sum(lst)`, `max(lst)`, `lst.count(x)` | O(n) | 전부 한 번씩 봐야 한다 |

반대로 O(1) 인 것: `lst[i]`, `lst.append(x)`, `lst.pop()`(맨 뒤), `len(lst)`, `d[key]`, `key in d`, `x in set`

## 실행 시간으로 거꾸로 알아내기

입력을 2배로 늘려 시간을 재면, 몇 배가 됐는지로 복잡도를 짐작할 수 있다.

| n이 2배일 때 시간이 | 복잡도 |
|---|---|
| 거의 그대로 | O(1) 또는 O(log n) |
| 2배 | O(n) |
| 4배 | O(n²) |
| 8배 | O(n³) |

채점 결과에서 작은 입력은 빠른데 큰 입력에서 갑자기 시간 초과가 나면,
**입력이 늘어난 폭보다 시간이 훨씬 가파르게 늘고 있는지** 확인한다.

## 입력 크기를 보고 목표 복잡도 정하기

파이썬은 1초에 **단순 연산 수천만 번** 정도를 한다 (이 컴퓨터에서 잰 값: 약 3천만 번).
채점 서버는 이보다 느릴 수 있으니 여유 있게 잡는다.

문제의 입력 제한을 보고, 이 안에 들어오는 복잡도를 고른다. **대략적인 기준**이다.

| n 최대 | 통과 가능한 복잡도 (파이썬) |
|---|---|
| 10 안팎 | 뭐든 된다. 모든 경우 다 해보기(완전 탐색)도 가능 |
| 수백 (~300) | O(n³) 까지 |
| 수천 (~5,000) | O(n²) 까지 |
| 수십만 ~ 100만 | O(n log n) 까지 |
| 1000만 | O(n) |

**문제를 풀기 전에 먼저 계산해 본다.** 입력 제한을 넣어서 작업 횟수가 1억을 훌쩍 넘으면 그 방식은 버린다.

예시:

- 달리기 경주: 선수 5만, 부름 100만. `index()` 방식은 5만 × 100만 = **500억** → 불가능. O(n + m) 이 필요하다
- 삼각 달팽이: n ≤ 1000. 칸이 약 50만 개라 **O(n²) = 칸마다 한 번**은 괜찮다. O(n³) = 10억은 안 된다
